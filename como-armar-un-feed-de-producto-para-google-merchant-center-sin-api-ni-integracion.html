Cómo armar un feed de producto para Google Merchant Center sin API ni integración

Un feed para Google Shopping sin API sale del JSON-LD de cada ficha. La mitad se rechaza por campos que nadie revisó.

El caso típico: una tienda con 4.000 SKU quiere aparecer en Google Shopping. No hay acceso a la Admin API de la plataforma, o sí lo hay pero el cliente no paga la app de integración por rango de SKU. Alguien arma un CSV a mano desde el panel, lo sube a Merchant Center y a los tres días aparecen 900 productos "no aprobados" con motivos que suenan iguales: precio, disponibilidad, imagen.

La salida no es un scraper de HTML. Es leer el mismo bloque que la tienda ya publica para Google: el Product en JSON-LD. Está en la ficha, es público, no requiere token y es contra lo que el rastreador de Merchant Center compara tu feed. Si el feed y el JSON-LD dicen cosas distintas, te rechazan el ítem.

Por qué se rechaza el feed aunque el CSV esté perfecto

De los motivos de desaprobación, cuatro dependen de la landing, no del archivo:

  • Precio distinto. El CSV dice 39.990 y la ficha muestra 35.990 porque hubo una promoción que no se replicó. Google rastrea la ficha, compara y desaprueba.
  • Disponibilidad distinta. El feed dice in stock, la ficha muestra "sin stock". Pasa siempre con catálogos grandes que se actualizan dos veces por semana.
  • Precio con formato local. 39.990 se lee como treinta y nueve con noventa y nueve. El feed espera 39990.00 ARS: número, espacio, código ISO 4217.
  • gtin inventado o vacío. Si el producto no tiene GTIN, hay que declarar identifier_exists=no. Poner un código cualquiera es peor que dejarlo vacío.

Los otros dos motivos son del archivo: image_link que devuelve 403 o mide menos de 100x100 px, y link con parámetros de tracking o redirecciones que no coinciden con la URL final.

Paso 1 — Extraer el Product del JSON-LD

Node 18+ alcanza. El script lee la ficha, junta todos los bloques application/ld+json, aplana @graph y se queda con el nodo Product:


// ld-feed.mjs — uso: node ld-feed.mjs https://tienda.com/producto
const AVAIL = {
  'https://schema.org/InStock': 'in stock',
  'https://schema.org/OutOfStock': 'out of stock',
  'https://schema.org/PreOrder': 'preorder',
  'https://schema.org/BackOrder': 'backorder',
};

async function jsonLdBlocks(url) {
  const res = await fetch(url, { headers: { 'User-Agent': 'feed-audit/1.0 (+contacto@tudominio.com)' } });
  if (!res.ok) throw new Error(`HTTP ${res.status} en ${url}`);
  const html = await res.text();
  // El atributo type puede venir sin comillas (HTML válido) y ahí se rompen la mitad de los parsers.
  const blocks = [...html.matchAll(/<script[^>]+type\s*=\s*["']?application\/ld\+json["']?[^>]*>([\s\S]*?)<\/script>/gi)];
  return blocks.map((m) => m[1]);
}

function flatten(node, acc = []) {
  if (Array.isArray(node)) { node.forEach((n) => flatten(n, acc)); return acc; }
  if (!node || typeof node !== 'object') return acc;
  acc.push(node);
  if (node['@graph']) flatten(node['@graph'], acc);
  return acc;
}

const typeOf = (n) => (Array.isArray(n['@type']) ? n['@type'] : n['@type'] ? [n['@type']] : []);

const nodes = (await jsonLdBlocks('https://tienda.com/producto')).flatMap((raw) => {
  try { return flatten(JSON.parse(raw)); } catch { return []; } // un bloque roto no debe tumbar el lote
});

const product = nodes.find((n) => typeOf(n).includes('Product'))
  ?? nodes.find((n) => typeOf(n).includes('ProductGroup'));
if (!product) throw new Error('La ficha no publica Product en JSON-LD');

const offer = Array.isArray(product.offers)
  ? product.offers[0]
  : (product.offers ?? product.hasVariant?.[0]?.offers ?? {});
const price = offer.price ?? offer.priceSpecification?.price;
const currency = offer.priceCurrency ?? offer.priceSpecification?.priceCurrency;
const brand = typeof product.brand === 'string' ? product.brand : product.brand?.name;
const gtin = product.gtin13 ?? product.gtin12 ?? product.gtin ?? product.mpn;

console.log({
  id: product.sku ?? product.productID ?? '',
  title: (product.name ?? '').slice(0, 150),
  availability: AVAIL[offer.availability] ?? 'in stock',
  price: price == null ? '' : `${Number(price).toFixed(2)} ${currency ?? ''}`.trim(),
  brand, gtin, image: Array.isArray(product.image) ? product.image[0] : product.image,
});

Tres detalles que aparecen en producción y no en los tutoriales:

  • offers puede ser un array, un objeto o no existir. En tiendas con variantes el precio vive en hasVariant[].offers[]. Si asumís objeto, offer.price te da undefined y el feed sale con la columna de precio vacía sin lanzar ningún error.
  • price viene como string. "269999.00" sin Number() se concatena en vez de sumar, y cualquier cálculo de margen o de variación queda mal sin avisar.
  • El bloque JSON-LD puede ser inválido. Una coma de más en un bloque no debe cortar el lote de 4.000 URLs: por eso el try/catch está por bloque y no por página.

Paso 2 — Mapear a las columnas del feed

Merchant Center acepta TSV, XML o API. El TSV es el más simple de generar y de auditar con un diff. Estas son las columnas que necesita un ítem de producto:

  • id — sku o productID. Estable entre corridas, si no se duplican ítems.
  • title — name. Máximo 150 caracteres; se trunca, no se rechaza.
  • description — description. Máximo 5.000 caracteres, sin HTML.
  • link — URL canónica de la ficha, sin parámetros de tracking ni redirecciones.
  • image_link — image[0]. Pública, sin login, mínimo 100x100 px.
  • availability — offers.availability. in stock, out of stock, preorder o backorder.
  • price — offers.price + priceCurrency. 39990.00 ARS, con espacio y código ISO 4217.
  • brand — brand.name. Requerido en la mayoría de las categorías.
  • gtin — gtin13 / gtin12 / gtin8. Vacío obliga a identifier_exists=no.
  • condition — offers.itemCondition. new salvo que vendas usados.

El id es la decisión que más se ignora. Si usás el título o el índice de la fila, cada corrida genera ítems nuevos y Merchant Center acumula duplicados hasta inutilizar el catálogo.

Paso 3 — Recorrer el catálogo y validar antes de subir

Con una URL funciona. Con 4.000 necesitás dos cosas: la lista de URLs y un chequeo previo. La lista sale del sitemap.xml de la tienda (o de sitemap_products_1.xml en Shopify); el chequeo es este:


const rows = []; // una fila por ficha, ya extraída
const problemas = { sinGtin: 0, sinPrecio: 0, sinImagen: 0 };
for (const r of rows) {
  if (!r.gtin) problemas.sinGtin++;
  if (!r.price) problemas.sinPrecio++;
  if (!r.image) problemas.sinImagen++;
}
console.log(`${rows.length} filas`, problemas);

Si sinPrecio o sinImagen dan distinto de cero, no subas el feed: esos ítems se van a desaprobar y te van a tapar el diagnóstico de los demás.

Corrélo sobre veinte fichas antes de escribir el pipeline y mirá la columna gtin. En la primera tienda donde probé este script —un retailer argentino— el JSON-LD traía nombre, imagen y precio, pero ningún GTIN. No es un bug del script: es el catálogo real, y es lo que el feed tiene que declarar con identifier_exists=no.

Lo que este método no resuelve

  • Una fila por página, no por variante. Si la tienda vende el mismo buzo en cinco talles, este script devuelve una fila. Para variantes hace falta leer hasVariant[] y generar item_group_id más un id distinto por variante; cada plataforma lo publica con otra forma.
  • Fichas sin JSON-LD. Hay tiendas que solo emiten microdata o nada; ahí el feed sale de la API de la plataforma o del HTML, y el mantenimiento se multiplica.
  • Varios países o monedas. Un feed es por país y idioma de destino. Si la tienda sirve precios distintos según geografía, necesitás una corrida por mercado, no una tabla con todo mezclado.
  • Precios que cambian todo el día. El feed es una foto; si el precio cambia cada hora necesitás actualización programada, y eso ya es infraestructura.
  • Bloqueos del origen. Muchas tiendas grandes responden 403 o 429 desde servidores: el script corre en tu máquina y falla en un VPS sin proxy.

Si el cliente tiene una tienda y actualiza el feed una vez por semana, el script sobra. Si tiene seis tiendas, cada una con otra plataforma, el trabajo real deja de ser el parseo y pasa a ser la paginación, los reintentos, el proxy y el diff entre corridas.
