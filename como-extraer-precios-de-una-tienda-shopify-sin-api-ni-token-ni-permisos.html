Cómo extraer precios de una tienda Shopify sin API (ni token, ni permisos)

Si trabajás en una agencia o tenés un e-commerce propio, tarde o temprano llega el pedido:

"necesito los precios de estas 12 tiendas de la competencia, actualizados cada semana".

La respuesta que aparece primero en Google es la Admin API de Shopify. El problema es que la

Admin API requiere ser el dueño de la tienda: instalás una app, generás un token con scope

read_products y listo. Para tu propia tienda funciona. Para las tiendas de otros, no existe.

No hay forma legítima de pedirle un token a un competidor.

Entonces la tarea se degrada a lo que hacen muchas agencias: alguien abre 12 pestañas, copia

precios a un Excel y lo repite cada lunes. Con 300 SKU por tienda son 3.600 filas manuales por

semana. Ese trabajo no lo paga ningún cliente.

Hay una salida intermedia que casi nadie usa: la mayoría de las tiendas Shopify exponen su

catálogo en endpoints públicos en JSON, los mismos que alimentan los temas y las integraciones

de marketing. No hace falta token, no hace falta headless browser y no hace falta scraping de

HTML.

El endpoint que sí existe

Toda tienda Shopify responde, por defecto, a dos rutas:


https://tienda.com/products.json
https://tienda.com/collections/<handle>/products.json

La primera devuelve el catálogo completo paginado; la segunda, solo los productos de una

colección concreta. Son las mismas rutas que usa el tema para renderizar listados y buscadores

internos. Aceptan tres parámetros útiles:

| Parámetro | Valor | Qué hace |

|---|---|---|

| limit | 1–250 | Productos por página. 250 es el máximo real. |

| page | 1..n | Número de página. |

| published_status | published | Filtra borradores (a veces ignorado en la ruta pública). |

Un detalle que rompe scripts: la respuesta no incluye el total de páginas. La única forma

de saber cuándo terminar es pedir páginas hasta que devuelva un array vacío. Si tu script asume

que hay 20 páginas y corta ahí, vas a perder catálogo en tiendas grandes sin ningún error

visible.

Probá primero a mano, desde la terminal:


curl -s "https://gymshark.com/products.json?limit=2&page=1" | head -c 600

Si ves un objeto con "products": [...], la tienda está abierta. Si ves un 404 o un HTML de

página de error, el merchant desactivó la ruta (pasa: algunos temas y apps de seguridad la

bloquean). En ese caso hay que ir por sitemap_products_1.xml o por el JSON-LD del HTML, que

es otro artículo.

El formato de los precios

Cada producto trae un array variants. El precio está a nivel variante, no a nivel producto,

porque un mismo producto puede tener talle S a un precio y talle XL a otro. Los campos que

importan:


{
  "handle": "seamless-workout-leggings",
  "title": "Seamless Workout Leggings",
  "updated_at": "2026-10-28T14:02:11-04:00",
  "variants": [
    {
      "sku": "LEG-BLK-S",
      "title": "S / Black",
      "price": "39.90",
      "compare_at_price": "49.90",
      "available": true
    }
  ]
}

Tres trampas concretas:

1. price es un string decimal, no un número. "39.90" sumado sin Number() te da

concatenación de texto en JavaScript y columnas destruidas en el CSV.

2. En /products.json los precios vienen en unidades, no en centavos. La Admin API sí usa

centavos (3990). Mezclar las dos fuentes en el mismo pipeline es el bug clásico que

multiplica todos los precios por 100 en un solo reporte.

3. compare_at_price puede ser null. Ese es el precio "antes de descuento". Si lo tratás

como número sin chequear, el descuento calculado te da NaN y el reporte de "quién bajó

precios" queda vacío sin avisar.

available es útil para distinguir "bajó el precio" de "se quedó sin stock y el precio viejo

quedó congelado". Sin ese campo, un quiebre de stock parece una suba de precio.

Script mínimo, sin dependencias

Node 18+ ya trae fetch. Este script recorre el catálogo completo, respeta la paginación y

escribe un CSV con una fila por variante:


// shopify-prices.mjs — uso: node shopify-prices.mjs https://tienda.com precios.csv
import { writeFile } from 'node:fs/promises';

const [, , store, out = 'precios.csv'] = process.argv;
if (!store) {
  console.error('Uso: node shopify-prices.mjs https://tienda.com [salida.csv]');
  process.exit(1);
}

const base = store.replace(/\/+$/, '');
const LIMIT = 250;

async function fetchPage(page) {
  const url = `${base}/products.json?limit=${LIMIT}&page=${page}`;
  const res = await fetch(url, {
    headers: { 'User-Agent': 'price-audit/1.0 (+contacto@tudominio.com)' },
  });
  if (!res.ok) throw new Error(`HTTP ${res.status} en ${url}`);
  const body = await res.json();
  return Array.isArray(body.products) ? body.products : [];
}

const rows = [];
for (let page = 1; ; page++) {
  const products = await fetchPage(page);
  if (products.length === 0) break;

  for (const p of products) {
    for (const v of p.variants ?? []) {
      rows.push({
        handle: p.handle,
        product: p.title,
        sku: v.sku ?? '',
        variant: v.title,
        price: Number(v.price).toFixed(2),
        compare_at: v.compare_at_price == null ? '' : Number(v.compare_at_price).toFixed(2),
        available: v.available === true ? 'yes' : 'no',
        updated_at: p.updated_at ?? '',
      });
    }
  }

  if (products.length < LIMIT) break;
  await new Promise((r) => setTimeout(r, 1200)); // cortesía: no martillar el origen
}

if (rows.length === 0) throw new Error('Catálogo vacío o ruta /products.json deshabilitada');

const headers = Object.keys(rows[0]);
const escape = (val) => `"${String(val).replace(/"/g, '""')}"`;
const csv = [
  headers.join(','),
  ...rows.map((r) => headers.map((h) => escape(r[h])).join(',')),
].join('\n');

await writeFile(out, csv, 'utf8');
console.log(`${rows.length} variantes → ${out}`);

Corrélo y compará dos fechas:


node shopify-prices.mjs https://tienda-a.com lunes.csv
node shopify-prices.mjs https://tienda-a.com jueves.csv

Con dos CSV, un join por sku te da el diff de precios. Ahí aparece el dato que el cliente

paga: qué variante subió, cuánto y desde cuándo (updated_at lo confirma).

Lo que este método no resuelve

Vale ser explícito, porque acá se rompen la mitad de las promesas de scraping:

  • Precios por geografía o por moneda. Si la tienda sirve precios distintos según el país del

visitante, /products.json devuelve el precio de la moneda de la tienda, no el que ve tu

cliente en México. Para eso hace falta proxy con geo y renderizado de la página real.

  • Catálogos B2B con login. Si el precio está detrás de una sesión, no hay endpoint público

que lo exponga.

  • Volumen alto desde una sola IP. Shopify aplica rate limiting suave y puede devolver 429 o

páginas vacías. El sleep del script no es decorativo; y para 50 tiendas en paralelo conviene

proxy.

  • Tiendas con la ruta bloqueada. Ahí hay que parsear el HTML, que es entre 5 y 10 veces más

caro en tiempo y en mantenimiento.

Si el volumen es de una tienda y una vez por semana, el script de arriba sobra. Si el cliente

quiere 40 tiendas monitoreadas todos los días, con historial y alertas, mantener el script pasa

a ser tu trabajo no pago.
