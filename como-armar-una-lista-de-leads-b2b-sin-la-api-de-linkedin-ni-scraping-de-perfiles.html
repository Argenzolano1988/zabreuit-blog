Cómo armar una lista de leads B2B sin la API de LinkedIn ni scraping de perfiles

Una lista de empresas con contacto público se arma con el sitio de cada empresa, registros públicos y cinco pasos. Método completo, con código.

El pedido típico: "necesito 500 empresas de logística en Argentina y Uruguay, con el responsable de compras y un email que funcione". La respuesta automática es buscar un exportador de LinkedIn. Ahí empieza el problema.

Por qué el atajo de LinkedIn no cierra

La API existe, pero no es un buscador de personas: el acceso a datos de miembros va por programas de partner con aprobación comercial, campos acotados y condiciones que excluyen armar bases propias para prospección masiva.

El scraping de perfiles tiene el problema inverso: funciona hasta que la cuenta desaparece. Y aunque sobreviva, devuelve un cargo y una empresa, nunca un email. El email se adivina con un patrón (nombre.apellido@empresa.com), y cada dirección inventada que no existe es un rebote.

El camino menos vistoso que sí escala es usar lo que la empresa publica por obligación o por interés comercial: sitio corporativo, datos estructurados, páginas de contacto y equipo, directorios de cámaras, registros de proveedores del Estado.

Qué cuenta como decisor público

No vas a obtener el organigrama interno. Lo que suele estar publicado:

  • Página de equipo o "nosotros" con nombres y cargos.
  • Firmas de comunicados de prensa.
  • Representante legal en un registro público de sociedades.
  • Responsable de compras en pliegos de licitación y actas de adjudicación.

Si el cargo no aparece en ninguno de esos lugares, no hay dato: hay una suposición. Un pipeline honesto deja la fila vacía en vez de inventar un nombre.

Paso 1: descubrir el dominio

La lista de empresas rara vez trae dominio; trae razón social, ciudad y rubro. Fuentes que rinden:

  • Directorios de cámaras sectoriales y binacionales, con socio, rubro, teléfono y sitio.
  • Listas de expositores de ferias del rubro.
  • Registros de proveedores del Estado, con CUIT/CNPJ y a veces el sitio.
  • Búsquedas por rubro y ciudad, descartando agregadores.

Resolver nombre a dominio es mecánico; descartar falsos positivos no. Dos chequeos baratos: el dominio tiene MX activo y la home menciona la razón social, la ciudad o el rubro. Un dominio parqueado con publicidad pasa el primero y falla el segundo.

Paso 2: extraer la entidad del propio sitio

Muchos sitios corporativos ya publican sus datos en JSON-LD, el mismo bloque que usan los buscadores para entender la empresa. Se lee del HTML sin renderizar JavaScript y sin pelear con selectores que cambian cada tres meses.


// entity-from-html.mjs — devuelve todos los nodos Organization del sitio
export function parseJsonLd(html) {
  const blocks = [...html.matchAll(/<script[^>]+type=["']application\/ld\+json["'][^>]*>([\s\S]*?)<\/script>/gi)];
  const found = [];

  for (const [, raw] of blocks) {
    let data;
    try {
      data = JSON.parse(raw.replace(/<!--|-->/g, "").trim());
    } catch {
      continue; // bloque roto: se ignora, no se aborta el sitio
    }
    const queue = Array.isArray(data) ? [...data] : [data];
    while (queue.length) {
      const node = queue.shift();
      if (!node || typeof node !== "object") continue;
      if (Array.isArray(node["@graph"])) queue.push(...node["@graph"]);
      const types = [].concat(node["@type"] ?? []);
      if (types.some((t) => t === "Organization" || t === "Corporation" || t === "LocalBusiness")) {
        found.push(node);
      }
    }
  }
  return found;
}

Los campos que interesan son name, legalName, email, telephone, vatID, taxID y address.

Sin JSON-LD, el fallback es la página de contacto: enlaces mailto: y wa.me, más el pie de página. Es más frágil, así que se marca source: "html-fallback" y se revisa a mano.

Dos trampas:

  • @graph anidado. Muchos sitios envuelven todo en {"@context": ..., "@graph": [...]}. Si solo mirás el primer nivel, no encontrás nada.
  • JSON-LD inválido. Comentarios HTML, comas finales o comillas curvas rompen JSON.parse. Un try/catch por bloque evita perder la página entera por un error.

Paso 3: normalizar antes de comparar

  • Dominio: minúsculas, sin www, sin protocolo ni path. Guardar el host original para auditar.
  • Email: minúsculas, sin mailto:. Contacto@ y contacto@ rompen cualquier GROUP BY ingenuo.
  • Teléfono: a E.164. 11 4321-0000, +54 11 4321 0000 y 01143210000 son tres filas si no se normaliza.
  • Razón social: sacar S.A., S.R.L., SAS, Ltda., LLC, puntos y dobles espacios; guardar el crudo aparte.

Deduplicar es comparar. Comparar basura normalizada agrupa basura.

Paso 4: deduplicar con la clave correcta

La clave natural es el dominio registrable, pero calcularlo con split(".") es el error más común: tienda.com.ar unido por los dos últimos segmentos devuelve com.ar, así que todas las empresas argentinas caen en la misma fila.


const MULTI = new Set(["com.ar", "com.br", "com.mx", "com.co", "com.uy", "com.pe", "co.uk", "com.es"]);

export function registrableDomain(host) {
  const parts = host.toLowerCase().replace(/^www\./, "").split(".").filter(Boolean);
  if (parts.length <= 2) return parts.join(".");
  const lastTwo = parts.slice(-2).join(".");
  return MULTI.has(lastTwo) ? parts.slice(-3).join(".") : lastTwo;
}

Después del dominio, el segundo criterio es el teléfono normalizado: hay grupos que publican la misma central en cinco sitios. El tercero es el CUIT/CNPJ cuando aparece.

Lo que no conviene es deduplicar por nombre con distancia de edición. "Logística Sur" y "Logística del Sur" pueden ser dos empresas, y fusionarlas borra un lead real sin aviso.

Paso 5: verificar antes de exportar

  • MX del dominio. resolveMx con al menos un registro significa que puede recibir correo; cero registros, que el email es decorativo.
  • Estado HTTP de la fuente. Un 404 o 403 al extraer indica pie de página viejo o bloqueo: reintentar o descartar.
  • Nombre del buzón. info@, ventas@ y contacto@ sirven para prospección general, no para "el responsable de compras". Etiquetarlos permite priorizar.

Lo que no se puede prometer es que la casilla exista. Un servidor catch-all acepta cualquier dirección, así que una verificación SMTP dice "válido" para cualquiercosa@empresa.com; y el greylisting da error para una casilla que sí existe. El MX reduce ruido, no certifica el buzón.

Dónde se rompe

  • Sitios renderizados en el cliente. Si el HTML inicial viene vacío, el JSON-LD puede estar inyectado por JavaScript.
  • Directorios sin IDs estables. Las fichas cambian de URL y el negocio aparece dos veces. Se resuelve con huella de contenido (nombre normalizado + teléfono), no con la URL.
  • Personas físicas. Un email con nombre y apellido es dato personal: bajo Ley 25.326 o LGPD, la base legal y el derecho de oposición aplican aunque el dato sea público. Definí quién procesa una baja antes de importar a un CRM.
  • Volumen. Cien dominios salen en minutos con cortesía entre requests; diez mil piden proxy, reintentos y cola. Eso ya es infraestructura.
