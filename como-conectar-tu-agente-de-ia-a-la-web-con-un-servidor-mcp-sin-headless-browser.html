Cómo conectar tu agente de IA a la web con un servidor MCP (sin headless browser)

Tu agente no ve la web: le pegás HTML a mano o levantás un Chromium por consulta. Un servidor MCP de 60 líneas resuelve ese acceso sin browser.

En una sesión de Cursor o Claude Desktop el pedido suena simple: "mirá la página de precios de este competidor y compará los tres planes". El agente contesta de memoria, con precios de hace dos versiones, o directamente inventa. No es culpa del modelo: el proceso donde corre no tiene manos. Ve tus archivos, no la web.

Hay tres formas de darle acceso y dos son malas.

La primera es copiar y pegar el HTML. Funciona una vez, no funciona cuando el pipeline tiene que correr cien URLs por semana, y encima mete al contexto todo el menú, el banner de cookies y el footer.

La segunda es levantar un headless browser. Playwright o Puppeteer te dan una página renderizada de verdad, pero cada consulta arranca un Chromium que come entre 300 MB y 1,5 GB de RAM, tarda de 1 a 3 segundos y, si el sitio está detrás de Cloudflare, te devuelve el desafío igual. Para un agente que consulta cinco páginas por conversación, es un costo que no cierra.

La tercera es un servidor MCP: un proceso chico que expone funciones ("tools") y que el cliente del agente arranca solo. No hay daemon, no hay puerto, no hay browser. Es la opción que vamos a construir y probar acá, y después te muestro dónde se rompe.

Qué es MCP exactamente

El Model Context Protocol es JSON-RPC 2.0 sobre stdio. Nada más. El cliente (Claude Desktop, Cursor, Windsurf) lanza tu proceso como hijo y le escribe mensajes de una línea por stdin. Tu servidor contesta por stdout, también una línea por mensaje.

El ciclo mínimo tiene cuatro mensajes:

  • initialize: el cliente pregunta versión de protocolo y capabilities.
  • notifications/initialized: aviso del cliente, no lleva respuesta.
  • tools/list: el servidor devuelve el catálogo de tools con su JSON Schema.
  • tools/call: el cliente invoca una tool con argumentos y recibe el contenido.

Dos reglas que rompen servidores novatos: stdout es solo protocolo (un console.log de debug corrompe el stream; los logs van a stderr), y las notificaciones no llevan id, así que no se responden.

El servidor mínimo, funcionando

Este archivo es un servidor MCP completo con una sola tool: descargar una URL y devolver su texto visible. Node 18+, cero dependencias.


#!/usr/bin/env node
// mcp-fetch.mjs — servidor MCP mínimo: una tool que devuelve el texto visible de una URL.
import { createInterface } from 'node:readline';

const TOOLS = [{
  name: 'fetch_text',
  description: 'Descarga una URL y devuelve su texto visible, sin etiquetas HTML.',
  inputSchema: {
    type: 'object',
    properties: { url: { type: 'string', description: 'URL absoluta http(s)' } },
    required: ['url'],
  },
}];

const send = (msg) => process.stdout.write(JSON.stringify(msg) + '\n');

async function fetchText(url) {
  const res = await fetch(url, { headers: { 'User-Agent': 'mcp-fetch/1.0' } });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  const html = await res.text();
  return html
    .replace(/<script[\s\S]*?<\/script>/gi, ' ')
    .replace(/<style[\s\S]*?<\/style>/gi, ' ')
    .replace(/<[^>]+>/g, ' ')
    .replace(/&nbsp;/g, ' ')
    .replace(/&amp;/g, '&')
    .replace(/\s+/g, ' ')
    .trim();
}

const handlers = {
  async initialize({ protocolVersion }) {
    return {
      protocolVersion: protocolVersion ?? '2025-06-18',
      capabilities: { tools: {} },
      serverInfo: { name: 'mcp-fetch', version: '1.0.0' },
    };
  },
  async ping() { return {}; },
  async 'tools/list'() { return { tools: TOOLS }; },
  async 'tools/call'({ name, arguments: args }) {
    if (name !== 'fetch_text') throw new Error(`tool desconocida: ${name}`);
    const text = await fetchText(args.url);
    return { content: [{ type: 'text', text }] };
  },
};

createInterface({ input: process.stdin }).on('line', async (line) => {
  if (!line.trim()) return;
  let req;
  try { req = JSON.parse(line); } catch { return; }        // línea rota: se ignora
  if (req.id === undefined) return;                        // notificación: no lleva respuesta
  try {
    const result = await handlers[req.method](req.params ?? {});
    send({ jsonrpc: '2.0', id: req.id, result });
  } catch (err) {
    send({ jsonrpc: '2.0', id: req.id, error: { code: -32603, message: String(err.message ?? err) } });
  }
});

Se prueba sin cliente, a mano:


printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"fetch_text","arguments":{"url":"https://example.com"}}}' \
  | node mcp-fetch.mjs

La primera línea devuelve el catálogo; la segunda, el texto de la página. Si eso responde, el resto es configuración.

Conectarlo al cliente

En Claude Desktop, el archivo es ~/Library/Application Support/Claude/claude_desktop_config.json en macOS y ~/.config/Claude/claude_desktop_config.json en Linux. En Cursor va en .cursor/mcp.json dentro del proyecto. El bloque es el mismo:


{
  "mcpServers": {
    "fetch": {
      "command": "node",
      "args": ["/ruta/absoluta/mcp-fetch.mjs"]
    }
  }
}

Reiniciás el cliente y la tool aparece en el selector. Desde ahí, "traeme el texto de esta URL y resumí los precios" deja de ser una alucinación y pasa a ser una llamada real.

Dónde se rompe el juguete de 60 líneas

Corrélo contra cinco sitios reales y vas a chocar con esto:

  • Sitios que renderizan en el cliente. Un fetch devuelve el HTML inicial. Si la página es una SPA de React o Next con datos cargados por JS, el texto útil no está ahí: te queda un <div id="root"> vacío. Ahí el headless browser sí era necesario.
  • Bloqueos por User-Agent o por IP. Cloudflare, DataDome y los WAF de e-commerce devuelven 403 o una página de desafío con estado 200. Tu tool entrega "Checking your browser" como si fuera contenido.
  • Ruido que se come el contexto. El replace de etiquetas no distingue artículo de navegación. En una nota de blog de 800 palabras el texto extraído puede traer 3.000 palabras de menú, footer y "suscribite". Eso se paga en tokens y empeora la respuesta.
  • Entidades y espacios raros. &amp;, &#8217; y non-breaking spaces rompen comparaciones de precios y nombres de producto. El ejemplo resuelve dos entidades; el mundo real tiene cientos.
  • Una URL por llamada, sin caché. Cien páginas son cien round-trips al modelo, cada uno con su latencia. Sin caché ni concurrencia, el agente tarda minutos.
  • Extracción no determinista. El modelo re-parsea el mismo HTML en cada corrida. Dos ejecuciones seguidas te dan dos formatos distintos, y el diff de precios deja de significar algo.

Ninguna de esas fallas es del protocolo. MCP funciona. Lo que falta es el trabajo aburrido: detección de plataforma, parsers por tipo de página, reintentos, proxy y normalización de datos.

La versión empaquetada

Ese trabajo es lo que hace zabreuit-mcp, un servidor MCP publicado en npm (unas 500 descargas en los últimos 30 días, medido el 4 de noviembre de 2026). Se instala sin clonar nada:


npx -y zabreuit-mcp

Expone cinco tools sobre el mismo protocolo que acabás de ver:

  • extract_ecommerce: producto desde JSON-LD, microdatos y OpenGraph (Shopify, WooCommerce, Magento, Amazon y cualquier tienda con Schema.org).
  • extract_leads: contacto B2B desde el sitio de una empresa — emails, links de WhatsApp, redes y huella tecnológica; opcionalmente resuelve MX y SPF por DNS.
  • extract_markdown_rag: convierte artículos y documentación en Markdown limpio con chunkSize configurable, para indexar sin arrastrar navegación.
  • audit_technical_seo: título, meta description, canonical, directivas robots, tarjetas OpenGraph/Twitter y cabeceras de seguridad (HSTS, CSP, X-Frame-Options).
  • list_pro_presets y extract_preset_pro: 100 presets comerciales por plataforma. Buscar el catálogo es libre; ejecutar un preset requiere licencia (ZABREUIT_LICENSE_KEY).

La configuración es la misma que la del ejemplo, cambiando el comando:


{
  "mcpServers": {
    "zabreuit": {
      "command": "npx",
      "args": ["-y", "zabreuit-mcp"],
      "env": { "ZABREUIT_LICENSE_KEY": "" }
    }
  }
}

La diferencia práctica no es la velocidad del fetch: es que la salida viene estructurada y estable. El agente recibe un objeto con precio, SKU y stock en vez de 40 KB de HTML para interpretar. Eso es lo que hace que una comparación de precios se pueda repetir mañana y dé el mismo esquema.

Límites honestos

No hace login, no resuelve captchas y no renderiza SPAs que dependen de JavaScript para pintar el contenido; para esos casos sigue haciendo falta un browser real. Tampoco reemplaza un pipeline de scraping a escala: si necesitás 50.000 páginas por día con proxy rotativo e historial, esto es una pieza, no la solución completa.

Si tu volumen es una docena de URLs por conversación, el servidor de 60 líneas de arriba alcanza y no necesitás nada más. Cuando empezás a escribir parsers por sitio y a manejar 403, ahí el paquete te ahorra el mantenimiento.
