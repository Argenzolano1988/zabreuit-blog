Cómo extraer datos financieros y de registros públicos sin API key (SEC, BCE y licitaciones)

Los datos financieros públicos ya están en JSON estable. Lo que falla no es el acceso: es la normalización y el deduplicado.

Casi todos los datasets financieros que se venden como "premium" salen de tres fuentes que no piden credenciales: los filings de la SEC, las referencias diarias de un banco central y los portales de contratación pública. No hay token, no hay plan de pago, no hay cuota comercial. Hay un límite de cortesía, un formato raro por fuente y un montón de registros repetidos.

Qué se consigue sin credenciales y qué no

Sin credenciales, de forma estable:

  • SEC EDGAR: listado de filings por emisor (data.sec.gov/submissions/), hechos XBRL por compañía (companyfacts) y búsqueda de texto completo.
  • Bancos centrales: tipos de cambio de referencia diarios en XML (BCE europeo, entre otros). Histórico completo, un archivo por día.
  • Contratación pública: portales que publican en OCDS o en Socrata. Consultas JSON con $limit/$offset y un campo de última actualización.
  • Boletines oficiales: HTML con un índice por fecha. No es cómodo, pero es público y no cambia de estructura dos veces por año.

Lo que no se consigue sin credenciales, y conviene decirlo antes de prometerlo: datos financieros privados, estados contables de empresas cerradas, cotizaciones intradiarias, y cualquier cosa detrás de un login. Si alguien te ofrece eso sin credenciales, está revendiendo la misma fuente pública que podés leer directamente.

Paso 1 — EDGAR: el emisor y sus filings

La SEC exige un User-Agent que identifique la aplicación con un contacto real. Sin eso devuelve 403, y no es un bloqueo de red: es política de uso. El límite práctico es 10 pedidos por segundo.

El CIK va con 10 dígitos, rellenado con ceros. Ese es el primer bug de todos los scrapers de EDGAR: CIK=320193 devuelve 404, CIK=0000320193 no.


// edgar.mjs — uso: node edgar.mjs 320193
const UA = 'zabreuit-research/1.0 (contacto@tudominio.com)';
const cik = (n) => String(n).replace(/\D/g, '').padStart(10, '0');

async function json(url) {
  const res = await fetch(url, { headers: { 'User-Agent': UA, 'Accept-Encoding': 'gzip, deflate' } });
  if (res.status === 403) throw new Error('403: User-Agent sin contacto declarado');
  if (!res.ok) throw new Error('HTTP ' + res.status + ' en ' + url);
  return res.json();
}

const sub = await json('https://data.sec.gov/submissions/CIK' + cik(process.argv[2]) + '.json');

// recent viene en columnas paralelas, no en objetos: hay que transponer.
const r = sub.filings.recent;
const filings = r.form.map((form, i) => ({
  form,
  filed: r.filingDate[i],
  period: r.reportDate[i],
  accession: r.accessionNumber[i],
  doc: r.primaryDocument[i],
}));

const tens = filings.filter((f) => f.form === '10-K').slice(0, 3);
for (const f of tens) {
  const acc = f.accession.replace(/-/g, '');
  console.log(f.filed, 'https://www.sec.gov/Archives/edgar/data/' + Number(process.argv[2]) + '/' + acc + '/' + f.doc);
}

Dos detalles que ahorran horas:

  • filings.recent trae los últimos ~1.000 filings. Para historia completa hay que seguir filings.files[], que son páginas adicionales del mismo esquema.
  • Los documentos son HTML o XBRL, no PDF. Un 10-K con XBRL inline se lee buscando los tags ix:nonfraction; convertir a texto plano y parsear con expresiones regulares sobre lenguaje natural es la forma más rápida de obtener números equivocados.

Paso 2 — Cifras: companyfacts y el problema del duplicado

companyfacts devuelve cada concepto contable con todos sus valores reportados. El mismo período aparece varias veces, porque lo reporta el 10-Q, después el 10-K, y a veces una enmienda 10-K/A.


const facts = await json('https://data.sec.gov/api/xbrl/companyfacts/CIK' + cik(320193) + '.json');
const usd = facts.facts['us-gaap'].Revenues.units.USD;

// Un valor por período: gana el filed más reciente.
const porPeriodo = new Map();
for (const v of usd) {
  if (!v.end || !v.val) continue;
  const prev = porPeriodo.get(v.end);
  if (!prev || v.filed > prev.filed) porPeriodo.set(v.end, v);
}

const serie = [...porPeriodo.values()].sort((a, b) => (a.end < b.end ? -1 : 1));
console.log(serie.slice(-4).map((v) => v.end + ' ' + v.val));

Reglas que evitan series rotas:

  • Deduplicar por (concepto, inicio, fin) quedándose con el filed mayor. Si no, un trimestre corregido aparece dos veces con valores distintos.
  • Filtrar por form: los valores marcados fy/fp sin frame pueden ser acumulados anuales dentro de un trimestral. Si comparás trimestres, quedate con los que tienen frame tipo CY2024Q1.
  • No sumar val de conceptos distintos para "reconstruir" una métrica. Si el emisor no reporta la etiqueta que buscás, la respuesta honesta es "no reportado", no un total inventado.

Paso 3 — Búsqueda de texto completo

El buscador de EDGAR expone el mismo endpoint JSON que usa la interfaz: https://efts.sec.gov/LATEST/search-index con los parámetros q, forms, dateRange. Devuelve hits.hits y un total.


const q = new URLSearchParams({
  q: '"supply chain disruption"',
  forms: '8-K',
  dateRange: 'custom',
  startdt: '2026-01-01',
  enddt: '2026-03-31',
  from: '0',
  size: '100',
});

const res = await json('https://efts.sec.gov/LATEST/search-index?' + q);
console.log(res.hits.total.value, 'resultados', res.hits.hits.length, 'en esta página');

Advertencia operativa: el endpoint no está documentado como API pública estable. Si necesitás historia larga, partí la consulta por trimestre y guardá el resultado en disco con la respuesta cruda. Así, cuando cambie, no perdés el corpus: solo el próximo pedido.

Paso 4 — Tipos de cambio sin servicio pago

El BCE europeo publica una referencia diaria en un XML de 5 KB. Un archivo por día, sin key, sin cuota. La trampa no es descargarlo: es usarlo bien.


const xml = await (await fetch('https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml')).text();
const fecha = xml.match(/time=['"]([0-9-]{10})['"]/)[1];
const tasas = Object.fromEntries(
  [...xml.matchAll(/currency=['"]([A-Z]{3})['"]\s+rate=['"]([0-9.]+)['"]/g)].map((m) => [m[1], Number(m[2])]),
);
console.log(fecha, 'USD', tasas.USD);

Tres errores que se repiten:

  • Convertir con la tasa de hoy un importe de hace dos años. Guardá (fecha, par, tasa) y convertí con la tasa del día del hecho, no del día de la corrida.
  • Guardar el importe convertido en lugar del original. Si cambiás de fuente de tasas, perdiste la posibilidad de recalcular. Guardá moneda original + tasa + fecha de tasa.
  • Redondear en cada paso. Guardá en enteros de la unidad mínima (centavos) y redondeá solo al imprimir.

Paso 5 — Licitaciones: cursor por fecha, no por página

Los portales OCDS y Socrata responden JSON. El patrón que funciona es incremental: pedir solo lo que cambió desde la última corrida, con un cursor guardado.


const since = process.env.LAST_RUN || '2026-11-01T00:00:00';
const url = new URL('https://<portal>/resource/<dataset>.json');
url.searchParams.set('$where', "updated_at > '" + since + "'");
url.searchParams.set('$order', 'updated_at ASC');
url.searchParams.set('$limit', '1000');
url.searchParams.set('$offset', '0');

const rows = await json(url.href);
const cursor = rows.length ? rows[rows.length - 1].updated_at : since;
console.log(rows.length, 'registros, nuevo cursor', cursor);

Sin $order estable, el $offset devuelve filas repetidas y saltea otras: la base no garantiza orden entre páginas. Y sin cursor por updated_at, la corrida diaria baja el catálogo completo para encontrar dos cambios.

Paso 6 — La verificación que evita publicar basura

Antes de escribir el JSON final, tres asserts. No son tests formales: son la diferencia entre un dataset y un archivo de basura silenciosa.


const ids = new Set();
for (const row of filas) {
  if (!row.id) throw new Error('registro sin id: ' + JSON.stringify(row).slice(0, 120));
  if (ids.has(row.id)) throw new Error('id duplicado: ' + row.id);
  ids.add(row.id);
  if (!Number.isInteger(row.amountCents)) throw new Error('importe no entero: ' + row.id);
}
if (!filas.length) throw new Error('corrida vacía: revisá el cursor antes de sobrescribir');

El último assert es el más importante. Si una corrida vuelve vacía por un cambio de esquema, y el script sobrescribe el archivo, perdiste el dataset entero. La regla es simple: corrida vacía no pisa archivo existente, avisa y sale con código distinto de cero.

Lo que no conviene automatizar

  • Leer PDFs escaneados. Requiere OCR y el resultado no es auditable. Si la fuente solo publica PDF, descargalo y procesalo aparte, no dentro del pipeline diario.
  • Deducir el CUIT/CIF/RUT de un nombre. Los registros públicos devuelven coincidencias, no identidades. Un match por nombre sin identificador es un dato inventado.
  • Cruzar datasets por nombre de empresa. "ACME S.A." y "ACME SA" son dos filas; el identificador fiscal es lo único que une registros sin falsos positivos.
