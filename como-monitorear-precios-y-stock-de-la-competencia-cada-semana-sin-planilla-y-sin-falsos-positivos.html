Cómo monitorear precios y stock de la competencia cada semana (sin planilla y sin falsos positivos)

Copiar precios a mano no escala. El trabajo real es el diff semanal: qué variante cambió, cuánto y si fue precio o quiebre de stock.

La escena se repite en cualquier agencia o tienda mediana: seis competidores, dos mil SKUs, una

reunión de precios todos los martes. La primera semana alguien baja los catálogos a mano y arma

un Excel. La segunda funciona. A la tercera el archivo tiene cuatro hojas, dos fórmulas rotas y

nadie sabe si el precio de "Air Max 90 / talle 42" subió 3% o si cambió la forma en que la tienda

escribe el número.

El problema visible es bajar el catálogo. El problema real es comparar dos corridas y decidir

qué merece una acción: un competidor que bajó 15%, un producto que se quedó sin stock, una lista de

precios nueva que todavía no llegó a la web.

Por qué un diff ingenuo no sirve

Comparar dos CSV con un diff de texto falla por motivos que no tienen nada que ver con el negocio:

  • El precio es un string con formato local. Una tienda devuelve "12.999,00", otra "12999.00" y

otra un entero en centavos. Si comparás texto, todo cambia todas las semanas.

  • Los IDs de variante no son estables. Si el merchant borra y recrea un producto, Shopify le asigna

otro id. Un diff por ID reporta "producto eliminado + producto nuevo" en vez de "mismo producto".

  • Las promociones ensucian la señal. compare_at_price cambia cuando arranca una campaña; el precio

de venta puede no moverse. Si mezclás los dos campos, cada promo es una alerta falsa.

  • El stock oscila. Un SKU que pasa de disponible a agotado y vuelve en dos días suele ser carga de

stock mal hecha, no un quiebre real. Reportarlo como evento es ruido.

La regla práctica: normalizá al capturar, no al comparar, y hacé el diff sobre una clave estable.

Capturar: un snapshot por corrida, en NDJSON

El formato que menos duele es una línea JSON por variante, ordenada por clave. Es append-only por

archivo, se puede inspeccionar con grep y no necesita base de datos:


snapshots/tienda.com/2026-11-16.ndjson
snapshots/tienda.com/2026-11-23.ndjson
snapshots/tienda.com/latest.ndjson   -> copia de la última corrida

Clave estable: handle#variantId, y el SKU como dato aparte para poder reenganchar productos

recreados. Guardá ocho semanas y borrá lo viejo: más historial no mejora la decisión.

El script (Node 18+, sin dependencias)


// monitor.mjs — node monitor.mjs https://tienda.com
import fs from "node:fs";
import path from "node:path";

const base = process.argv[2]?.replace(/\/$/, "");
if (!base) throw new Error("uso: node monitor.mjs https://tienda.com");

const host = new URL(base).hostname;
const dir = path.join("snapshots", host);
fs.mkdirSync(dir, { recursive: true });
const latest = path.join(dir, "latest.ndjson");

// "1.234,56" | "1234.56" -> número, sin separadores de miles
const parsePrice = (v) => {
  if (typeof v === "number") return v;
  const s = String(v).trim();
  const decimalComma = s.includes(",") && s.lastIndexOf(",") > s.lastIndexOf(".");
  const cleaned = decimalComma ? s.replace(/\./g, "").replace(",", ".") : s.replace(/,/g, "");
  const n = Number(cleaned.replace(/[^\d.-]/g, ""));
  return Number.isFinite(n) ? n : null;
};

async function catalog() {
  const out = new Map();
  for (let page = 1; ; page++) {
    const res = await fetch(`${base}/products.json?limit=250&page=${page}`, {
      headers: { "user-agent": "zabreuit-price-monitor/1.0 (+contacto)" },
    });
    if (!res.ok) throw new Error(`HTTP ${res.status} en page ${page}`);
    const { products } = await res.json();
    if (!products.length) break;
    for (const p of products) {
      for (const v of p.variants) {
        const price = parsePrice(v.price);
        if (price === null) continue;
        const key = `${p.handle}#${v.id}`;
        out.set(key, {
          key,
          sku: v.sku || "",
          title: `${p.title} — ${v.title}`,
          price,
          compareAt: parsePrice(v.compare_at_price) ?? 0,
          available: Boolean(v.available),
          updated: p.updated_at,
        });
      }
    }
    await new Promise((r) => setTimeout(r, 400)); // cortesía con el servidor
  }
  return out;
}

const now = await catalog();
const prev = fs.existsSync(latest)
  ? new Map(fs.readFileSync(latest, "utf8").trim().split("\n").filter(Boolean)
      .map((l) => JSON.parse(l)).map((r) => [r.key, r]))
  : null;

const events = [];
const MIN_DELTA = 0.5; // % — por debajo de esto es redondeo o formato, no decisión de precio

if (prev) {
  for (const [key, r] of now) {
    const before = prev.get(key);
    if (!before) {
      events.push(`| ${r.sku || "-"} | ${r.title} | nuevo | ${r.price} | - |`);
      continue;
    }
    const delta = before.price ? ((r.price - before.price) / before.price) * 100 : 0;
    if (Math.abs(delta) >= MIN_DELTA) {
      events.push(`| ${r.sku || "-"} | ${r.title} | precio | ${before.price} | ${r.price} (${delta.toFixed(1)}%) |`);
    }
    if (before.available !== r.available) {
      events.push(`| ${r.sku || "-"} | ${r.title} | ${r.available ? "volvió" : "sin stock"} | - | - |`);
    }
  }
  for (const [key, before] of prev) {
    if (!now.has(key)) events.push(`| ${before.sku || "-"} | ${before.title} | eliminado | ${before.price} | - |`);
  }
}

const snapshot = path.join(dir, `${new Date().toISOString().slice(0, 10)}.ndjson`);
fs.writeFileSync(snapshot, [...now.values()].map((r) => JSON.stringify(r)).join("\n") + "\n");
fs.copyFileSync(snapshot, latest);

if (!events.length) {
  console.log(`${now.size} variantes, sin cambios sobre el umbral`);
} else {
  const table = [
    `| SKU | Producto | Tipo | Antes | Ahora |`,
    `| --- | --- | --- | --- | --- |`,
    ...events,
  ].join("\n");
  fs.writeFileSync("diff.md", table + "\n");
  console.log(table);
}

Cuatro decisiones que están en el código y no en un comentario:

1. El umbral de 0,5% absorbe redondeos y cambios de formato, pero no una decisión de precio.

2. compareAt se guarda aparte y no entra al diff: sirve para explicar por qué cambió el precio

de venta, no para generar alertas.

3. El stock se reporta solo como transición (sin stock / volvió), no como estado. Así ves el

quiebre, no la lista de agotados que ya conocías.

4. La corrida nueva se escribe aunque no haya eventos. Si falla el fetch, el script corta antes

de tocar latest.ndjson, y la semana siguiente el diff sigue siendo contra la última corrida

buena, no contra un archivo vacío.

La salida es deliberadamente aburrida, para pegar en el chat del equipo:


| SKU | Producto | Tipo | Antes | Ahora |
| --- | --- | --- | --- | --- |
| 884726 | Air Max 90 — 42 | precio | 129990 | 118990 (-8.5%) |
| 884731 | Air Max 90 — 44 | sin stock | - | - |

Programarlo y no pensar más

Un cron semanal alcanza. El detalle es no mandar mensaje cuando no hay nada que decir: si el

reporte llega todas las semanas con la misma tabla vacía, el equipo lo ignora en un mes.


# martes 08:00, hora local del servidor
0 8 * * 2 cd /srv/precios && node monitor.mjs https://tienda.com && \
  [ -f diff.md ] && node avisar.mjs diff.md && rm diff.md

Si no tenés servidor, un GitHub Action con schedule corre lo mismo, pero necesita persistir el

snapshot entre ejecuciones: un commit en una rama snapshots o un artefacto con retención de ocho

semanas. Sin persistencia, todos los SKUs aparecen como "nuevos" cada semana.

Para varias tiendas, un for sobre una lista de URLs y un diff.md por tienda; el consolidado es

un cat de los archivos que existen.

Dónde esto no alcanza

  • Catálogo cerrado. Si products.json devuelve 403 o 404, el merchant bloqueó la ruta. Queda

sitemap + JSON-LD del HTML, que es más frágil y más lento.

  • 429 con local_rate_limited. Shopify limita products.json por IP y, en tiendas con

protección anti-bot, puede rechazar el cliente mientras curl responde 200. Si te pasa, capturá

con curl -s "$URL/products.json?limit=250&page=$p" y parseá el JSON con jq, o asumí que esa

tienda necesita sitemap + JSON-LD. Reintentar a ciegas empeora el bloqueo.

  • Precios que dependen del login. Listas B2B, descuentos por cliente o precios por región con

cookie no son catálogo público. Eso requiere credenciales del retailer o su API oficial.

  • Impuestos y moneda. En algunos mercados el precio del endpoint es neto y el de la web es con

IVA. Comparar uno con otro da un 21% de diferencia que no existe. Guardá la moneda y el régimen

de impuestos junto al precio, o compará siempre el mismo campo.

  • Marketplaces. En Mercado Libre el precio cambia por vendedor y por tipo de publicación; el

catálogo público no alcanza y la API oficial pide token.

  • Cortesía y términos. Es data pública de catálogo, pero cada sitio tiene su robots.txt y sus

términos. Un request cada 400 ms y un User-Agent identificable es el mínimo; si el sitio pide

bajar el ritmo, se baja.

  • La clave no es eterna. Si la tienda migra de plataforma, cambian handles e IDs. Ahí el

reenganche es por SKU/EAN, y conviene tratarlo como una corrida de "re descubrimiento" en vez de

una semana con cien productos nuevos.
