Cómo auditar SEO y OpenGraph de 100 URLs en una corrida (sin crawler de pago)

Auditar 100 URLs a mano no es lento: es imposible de repetir el mes siguiente sin olvidarse la mitad de los campos.

El pedido típico llega así: una agencia cierra una auditoría de e-commerce y necesita revisar 100 URLs

—fichas de producto, categorías, landings de campaña— antes de la reunión del viernes. Los datos que

piden son aburridos y siempre los mismos: estado HTTP, title, meta description, un solo H1, canonical,

robots, imagen de OpenGraph y alts de las imágenes.

La herramienta de escritorio que todos usan cuesta una licencia por asiento, y el plan gratuito corta a

500 URLs, que parece suficiente hasta que el cliente suma un segundo dominio y una migración. Además,

la mitad del equipo no tiene la herramienta instalada. El resultado conocido: alguien abre las URLs en

pestañas, copia títulos a una planilla y el reporte sale con 60 filas de 100.

Lo que sigue es un script de 80 líneas, sin dependencias, que hace ese trabajo en una corrida y deja un

CSV comparable entre meses. Después explico qué no cubre, porque ahí es donde se rompen las promesas.

Los cinco errores que aparecen siempre en una muestra de 100 URLs

Antes del código, el checklist real. En una muestra de cien páginas de un e-commerce mediano, estos son

los hallazgos que se repiten:

1. Canonical cruzado. La ficha apunta su canonical a la categoría "para no duplicar contenido".

Google termina indexando la categoría y la ficha desaparece del índice.

2. noindex heredado del staging. El sitio se lanzó copiando la configuración de pruebas. La home

está indexada, las 400 fichas no. Nadie lo ve porque el robots.txt sí está bien.

3. OpenGraph a medias. Hay og:title, falta og:image. El link se comparte en WhatsApp o LinkedIn

sin miniatura, y quien lo manda no se entera.

4. Tres H1 por página. Uno del logo, uno del título, uno del banner. No es una penalización directa,

pero rompe la jerarquía que el equipo de contenido cree que tiene.

5. Cadena de redirects. http → https, sin www → con www y una regla vieja del CMS en el medio.

Cada salto gasta tiempo de rastreo y el status final no es el que reporta la herramienta si solo

mira el primero.

Ninguno de estos se detecta mirando una página. Se detectan mirando cien y contando.

El script

Node 18 o superior ya trae fetch. No hace falta instalar nada, ni abrir un navegador headless.


// seo-audit.mjs — uso: node seo-audit.mjs urls.txt reporte.csv
import { readFile, writeFile } from 'node:fs/promises';

const [, , listPath, out = 'reporte.csv'] = process.argv;
if (!listPath) {
  console.error('Uso: node seo-audit.mjs urls.txt [salida.csv]');
  process.exit(1);
}

const urls = (await readFile(listPath, 'utf8'))
  .split('\n')
  .map((l) => l.trim())
  .filter((l) => l && !l.startsWith('#'));

const UA = 'seo-audit/1.0 (+contacto@tudominio.com)';

/** Lee un atributo de una etiqueta HTML, con comillas simples o dobles. */
function attr(tag, name) {
  const m = tag.match(new RegExp(`\\b${name}\\s*=\\s*("([^"]*)"|'([^']*)')`, 'i'));
  return m ? (m[2] ?? m[3] ?? '').trim() : '';
}

function metas(html) {
  const map = new Map();
  for (const tag of html.match(/<meta\b[^>]*>/gi) ?? []) {
    const key = (attr(tag, 'name') || attr(tag, 'property')).toLowerCase();
    if (key && !map.has(key)) map.set(key, attr(tag, 'content'));
  }
  return map;
}

function canonicalOf(html) {
  for (const tag of html.match(/<link\b[^>]*>/gi) ?? []) {
    if (attr(tag, 'rel').toLowerCase() === 'canonical') return attr(tag, 'href') || '';
  }
  return '';
}

async function fetchChain(url) {
  let current = url;
  let hops = 0;
  for (; hops <= 5; hops++) {
    const res = await fetch(current, {
      redirect: 'manual',
      headers: { 'user-agent': UA },
      signal: AbortSignal.timeout(20000),
    });
    if (res.status >= 300 && res.status < 400) {
      const loc = res.headers.get('location');
      if (!loc) return { res, current, hops };
      current = new URL(loc, current).toString();
      continue;
    }
    return { res, current, hops };
  }
  throw new Error('más de 5 redirects');
}

const rows = [];
for (const url of urls) {
  try {
    const { res, current, hops } = await fetchChain(url);
    const html = (await res.text()).slice(0, 400000);
    const meta = metas(html);
    const title = (html.match(/<title[^>]*>([\s\S]*?)<\/title>/i)?.[1] ?? '').replace(/\s+/g, ' ').trim();
    const ogImage = meta.get('og:image') ?? '';

    const imgs = html.match(/<img\b[^>]*>/gi) ?? [];
    const noAlt = imgs.filter((tag) => !attr(tag, 'alt')).length;

    const issues = [];
    if (res.status >= 400) issues.push(`HTTP_${res.status}`);
    if (!title) issues.push('SIN_TITLE');
    else if (title.length > 60) issues.push('TITLE_LARGO');
    if (!meta.get('description')) issues.push('SIN_DESCRIPTION');
    if (!ogImage) issues.push('SIN_OG_IMAGE');
    if (!meta.get('og:title')) issues.push('SIN_OG_TITLE');
    if ((html.match(/<h1\b/gi) ?? []).length !== 1) issues.push('H1_COUNT');
    if (/noindex/i.test(meta.get('robots') ?? '')) issues.push('NOINDEX');
    if (!canonicalOf(html)) issues.push('SIN_CANONICAL');
    if (hops > 0) issues.push('REDIRECT');
    if (noAlt > 0) issues.push('IMG_SIN_ALT');

    rows.push({
      url,
      status: res.status,
      final: current,
      hops,
      title,
      title_len: title.length,
      description_len: (meta.get('description') ?? '').length,
      h1: (html.match(/<h1\b/gi) ?? []).length,
      canonical: canonicalOf(html),
      robots: meta.get('robots') ?? '',
      og_image: ogImage ? new URL(ogImage, current).toString() : '',
      imgs: imgs.length,
      imgs_sin_alt: noAlt,
      issues: issues.join(' '),
    });
  } catch (err) {
    rows.push({ url, status: 'ERROR', final: url, hops: '', issues: String(err.message || err) });
  }
  await new Promise((r) => setTimeout(r, 150)); // cortesía con el origen
}

const headers = ['url', 'status', 'final', 'hops', 'title', 'title_len', 'description_len', 'h1',
  'canonical', 'robots', 'og_image', 'imgs', 'imgs_sin_alt', 'issues'];
const cell = (v) => `"${String(v ?? '').replace(/"/g, '""')}"`;
const csv = [headers.join(','), ...rows.map((r) => headers.map((h) => cell(r[h])).join(','))].join('\n');

await writeFile(out, csv, 'utf8');
const conProblemas = rows.filter((r) => r.issues).length;
console.log(`${rows.length} URLs · ${conProblemas} con hallazgos → ${out}`);

Con el CSV abierto en una planilla, la columna issues se filtra y el reporte de la reunión sale solo:

cuántas fichas sin og:image, cuántas con noindex, cuántas con más de un H1.

Por qué redirect: 'manual' es la línea que importa

Si dejás que fetch siga los redirects solo, te devuelve el status final y perdés el dato que el

cliente pregunta primero: cuántos saltos hay antes de llegar. Con manual, el script guarda cada

Location, reconstruye la URL absoluta con new URL(loc, current) —necesario porque muchos servidores

devuelven rutas relativas— y cuenta los saltos.

Dos detalles operativos del mismo bloque:

  • El corte a 5 saltos evita el loop de reglas mal escritas. Un ERR_TOO_MANY_REDIRECTS en el

navegador también existe en un script, y sin corte se cuelga la corrida completa.

  • AbortSignal.timeout(20000) es lo que separa 100 URLs en 40 segundos de una corrida trabada 20

minutos en el dominio que no responde. Sin timeout, una sola URL muerta arruina el lote.

Lo que este script no ve

Ser explícito acá es más útil que el código, porque define cuándo el script deja de alcanzar:

  • Páginas que se renderizan con JavaScript. fetch trae el HTML inicial. Si el <title> y los

productos se inyectan en el cliente, el script va a reportar SIN_TITLE en páginas que en el

navegador están perfectas. Antes de acusar al cliente, abrí una URL en el navegador con JS

deshabilitado y compará.

  • Bloqueos anti-bot. Cloudflare y similares devuelven 403 o un challenge. Eso no es un hallazgo de

SEO: es el sitio defendiéndose de un request sin navegador. Va a la columna issues como HTTP_403

y hay que leerlo con criterio.

  • Core Web Vitals. LCP, INP y CLS requieren datos de usuarios reales o un laboratorio. Un request

HTTP no mide render.

  • Renderizado social. Acá solo se verifica que las etiquetas og:* existan. Cómo se ve la tarjeta en

WhatsApp depende de que la imagen pese poco, tenga la proporción correcta y esté accesible sin login.

  • Contenido duplicado entre páginas. Eso necesita comparar textos, no leer metadatos.

Cuándo el script deja de convenir

El script hace una corrida de 100 URLs en menos de un minuto y no cuesta nada. El problema aparece con

el uso real de una agencia: 40 dominios por mes, un CSV por dominio, reintentos cuando el origen

devuelve 429, proxy cuando el sitio bloquea, y alguien que se acuerde de correrlo el día que corresponde.
