Cómo auditar la salud web que se degrada sola: cabeceras, TLS, CORS y vencimiento de dominio

Un certificado que vence en 12 días y un CORS abierto no rompen la home: rompen el checkout, y nadie los ve hasta que el cliente llama.

Ninguna auditoría de contenido mira esa capa: cabeceras que dejó de enviar el CDN nuevo, el certificado del origen que el balanceador ya no renueva, un CORS que quedó en * desde el deploy de pruebas y un dominio que vence porque la tarjeta del titular caducó. Nada de eso cambia el HTML ni mueve rankings: aparece cuando falla un pago. Y lo único irrecuperable es el dominio.

Qué se consigue sin credenciales y qué no

Sin API key se obtiene, de forma estable: cabeceras de seguridad de la respuesta final, el certificado TLS con caducidad, emisor y cadena, la respuesta al preflight CORS, los datos de RDAP (registro, vencimiento, status, nameservers) y registros DNS por DoH.

No se consigue, y conviene decirlo antes de cualquier propuesta: el registrante real (RDAP lo devuelve redactado por privacidad), la zona DNS completa (AXFR está cerrado salvo error de configuración), la reputación en blocklists y el cumplimiento real de cookies: un script detecta el píxel, pero decidir si el consentimiento es válido es trabajo legal.

Paso 1 — Cabeceras: medir la respuesta final, no el primer salto

El error más común es leer las cabeceras del 301 que redirige http a https: las políticas viajan en la respuesta final, y medir el primer salto reporta ausencia de HSTS en un sitio que sí lo manda.


// headers.mjs — uso: node headers.mjs https://ejemplo.com
const UA = 'web-health/1.0 (+contacto@tudominio.com)';
const CHECKS = {
  'strict-transport-security': (v) => {
    if (!v) return 'AUSENTE';
    const max = Number((v.match(/max-age=(\d+)/i) ?? [])[1] ?? 0);
    return !max ? 'SIN_MAX_AGE' : max < 15552000 ? `MAX_AGE_CORTO(${max}s)` : '';
  },
  'content-security-policy': (v) => (!v ? 'AUSENTE' : /'unsafe-inline'/.test(v) ? 'UNSAFE_INLINE' : ''),
  'x-frame-options': (v) => (v ? '' : 'AUSENTE'),
  'x-content-type-options': (v) => (v?.toLowerCase() === 'nosniff' ? '' : 'DISTINTO_DE_NOSNIFF'),
  'referrer-policy': (v) => (v ? '' : 'AUSENTE'),
};

export async function headerAudit(url) {
  const res = await fetch(url, {
    redirect: 'follow', headers: { 'user-agent': UA, accept: 'text/html,*/*' }, signal: AbortSignal.timeout(15000),
  });
  const issues = [];
  for (const [name, check] of Object.entries(CHECKS)) {
    const verdict = check(res.headers.get(name));
    if (verdict) issues.push(`${name.toUpperCase()}:${verdict}`);
  }
  // report-only no protege: el navegador reporta y deja pasar.
  const csp = res.headers.get('content-security-policy');
  if (!csp && res.headers.get('content-security-policy-report-only')) issues.push('CSP_SOLO_REPORT_ONLY');
  return { url: res.url, status: res.status, issues };
}

if (process.argv[2]) console.log(await headerAudit(process.argv[2]));

Importan tres: HSTS ausente o con max-age menor a seis meses, CSP ausente o solo en -report-only (informa, no protege) y X-Frame-Options ausente en páginas con sesión.

Advertencia para no inventar falsos positivos: la ausencia de la cabecera no prueba que el navegador no aplique la política. HSTS también se aplica por lista de precarga compilada; consultá https://hstspreload.org/api/v2/status?domain=ejemplo.com antes de escribir "sin HSTS".

Paso 2 — TLS: caducidad, cadena y nombre

curl avisa del certificado pero no deja el dato estructurado. node:tls sí, y además detecta cadena incompleta y SNI mal configurado.


// tls.mjs — uso: node tls.mjs ejemplo.com
import tls from 'node:tls';

export function certAudit(hostname, port = 443) {
  return new Promise((resolve) => {
    const socket = tls.connect(
      { host: hostname, port, servername: hostname, ALPNProtocols: ['h2', 'http/1.1'], timeout: 12000 },
      () => {
        const leaf = socket.getPeerCertificate(true);
        const chain = [];
        for (let c = leaf; c && chain.length < 6; c = c.issuerCertificate) {
          chain.push(c.subject?.CN ?? '?');
          if (c.issuerCertificate === c) break; // raíz: se autorreferencia
        }
        const daysLeft = Math.round((new Date(leaf.valid_to) - Date.now()) / 86400000);
        resolve({
          authorized: socket.authorized, authError: socket.authorizationError ?? null,
          issuer: leaf.issuer?.O ?? '', validTo: leaf.valid_to, daysLeft,
          chain: chain.join(' > '), alpn: socket.alpnProtocol,
        });
        socket.end();
      },
    );
    socket.setTimeout(12000);
    socket.once('timeout', () => {
      socket.destroy();
      resolve({ host: hostname, error: 'timeout TLS' });
    });
    socket.once('error', (err) => resolve({ host: hostname, error: err.code ?? err.message }));
  });
}

if (process.argv[2]) console.log(await certAudit(process.argv[2]));

daysLeft es el número que el cliente entiende sin explicación: 12 días sin renovación automática es una caída con fecha. servername es obligatorio, porque sin SNI el servidor devuelve el certificado por defecto del pool y el reporte dice "válido" para el cert de otro dominio. Y authorized: false no es un bug del script, es el hallazgo: nunca pongas rejectUnauthorized: false "para que no falle".

Paso 3 — CORS: el preflight con un Origin que no es tuyo

fetch de Node no permite fijar Origin (es cabecera prohibida), así que el preflight se hace con curl, que sí la envía:


curl -sS -o /dev/null -D - -X OPTIONS \
  -H "Origin: https://audit.example" \
  -H "Access-Control-Request-Method: GET" \
  https://api.ejemplo.com/v1/health | grep -i '^access-control\|^vary'
  • Sin access-control-allow-origin — no es CORS. Bloqueante para una API pública, correcto para HTML.
  • ** sin credenciales* — válido en APIs de solo lectura. No es vulnerabilidad.
  • ** con allow-credentials: true* — combinación que el navegador rechaza: el sitio cree que funciona y no funciona.
  • Eco del Origin sin allowlist — cualquier dominio lee la respuesta. Con credenciales es crítico.
  • 405 en el OPTIONS — el endpoint no implementa preflight. No es CORS roto.

El 405 es el que genera más informes equivocados; el eco sin Vary: Origin deja que una caché sirva la respuesta de un origen a otro.

Paso 4 — Dominio: RDAP y DNS sin WHOIS

WHOIS tiene rate limit por IP, formatos distintos por registrador y bloqueos. RDAP es JSON con esquema único y el bootstrap de IANA dice qué servidor atiende cada TLD.


// rdap.mjs — uso: node rdap.mjs ejemplo.com
let bootstrap = { at: 0, services: [] };

async function rdapBaseFor(tld) {
  if (Date.now() - bootstrap.at > 86400000 || !bootstrap.services.length) {
    const res = await fetch('https://data.iana.org/rdap/dns.json', { signal: AbortSignal.timeout(20000) });
    if (!res.ok) throw new Error('bootstrap IANA: HTTP ' + res.status);
    bootstrap = { at: Date.now(), services: (await res.json()).services };
  }
  for (const [tlds, urls] of bootstrap.services) {
    if (tlds.includes(tld)) return urls.find((u) => u.startsWith('https://')) ?? urls[0];
  }
  return null;
}

export async function domainAudit(name) {
  const tld = name.split('.').pop().toLowerCase();
  const base = await rdapBaseFor(tld);
  if (!base) return { name, error: 'TLD sin RDAP en el bootstrap' };
  const res = await fetch(new URL('domain/' + name, base.replace(/\/?$/, '/')), {
    redirect: 'follow',
    headers: { accept: 'application/rdap+json' },
    signal: AbortSignal.timeout(20000),
  });
  if (res.status === 404) return { name, error: '404: no registrado o TLD sin RDAP' };
  if (!res.ok) return { name, error: 'HTTP ' + res.status };
  const data = await res.json();
  const ev = Object.fromEntries((data.events ?? []).map((e) => [e.eventAction, e.eventDate]));
  const exp = ev.expiration ?? '';
  const daysLeft = exp ? Math.round((new Date(exp) - Date.now()) / 86400000) : null;
  return { name: data.ldhName ?? name, registration: ev.registration ?? '', expiration: exp, daysLeft,
    status: (data.status ?? []).join(', ') };
}

if (process.argv[2]) console.log(await domainAudit(process.argv[2]));

El bootstrap se cachea un día (~100 KB que cambian al sumar TLDs) y 404 no es "dominio libre": puede ser un TLD sin RDAP. status dice más que la fecha: client transfer prohibited es normal, pending delete y redemption period son avisos reales.

Para el resto de la infraestructura, DoH devuelve JSON y no depende del resolver de la máquina:


// dns.mjs — uso: node dns.mjs ejemplo.com
export async function dns(name, type, endpoint = 'https://dns.google/resolve') {
  const url = new URL(endpoint);
  url.searchParams.set('name', name);
  url.searchParams.set('type', type);
  const res = await fetch(url, {
    headers: { accept: 'application/dns-json' },
    signal: AbortSignal.timeout(15000),
  });
  if (!res.ok) throw new Error(`DNS ${type}: HTTP ${res.status}`);
  const data = await res.json();
  return { status: data.Status, answers: (data.Answer ?? []).map((a) => a.data) };
}

const domain = process.argv[2] ?? 'ejemplo.com';
const [caa, dmarc] = await Promise.all([dns(domain, 'CAA'), dns('_dmarc.' + domain, 'TXT')]);
console.log({ caa: caa.answers, dmarcStatus: dmarc.status, dmarc: dmarc.answers });

Status es el RCODE: 0 es NOERROR y 3 es NXDOMAIN. Un _dmarc con 3 es el hallazgo (el dominio manda correo sin política), y NOERROR con answers vacío tampoco es un registro presente. Un CAA con 0 issue "letsencrypt.org" bloquea la emisión en cualquier otra CA: es el "el certificado nuevo no se puede emitir" después de cambiar de proveedor.

Paso 5 — Reportar sin inventar hallazgos

Cuatro funciones sueltas no son un informe: falta una regla de severidad y una ventana de medición, o el CSV dice SIN_CSP en 80 dominios sin decir qué arreglar primero.

  • Crítica — rompe una función hoy: certificado vencido, authorized: false, dominio en pending delete.
  • Alta — ventana menor a 30 días sin renovación automática.
  • Media — configuración inválida: * con credenciales, CSP solo report-only, sin DMARC.
  • Baja — endurecimiento faltante: sin Referrer-Policy, sin Permissions-Policy.

Regla que separa un auditor de un generador de ruido: el script reporta lo observado en una fecha, no un veredicto. Decí "en la respuesta del 20/11/2026 no se observó strict-transport-security", no "el sitio no tiene HSTS".

  • curl -I para todo — los servidores sin HEAD devuelven cabeceras incompletas.
  • Medir el 301 en vez de la respuesta final — falsos "sin HSTS" en sitios que sí lo tienen.
  • Chequear TLS sin servername — devuelve el certificado del pool, no el del dominio.
  • rejectUnauthorized: false — el script nunca detecta un certificado inválido.
  • **Tratar ACAO: como vulnerabilidad* — falso positivo: sin credenciales es válido.
