Cómo verificar emails B2B antes de enviar 1.000 contactos (sin servicio de pago)

Una lista de 1.000 contactos B2B se rompe en el primer envío: el proveedor frena la cuenta y el dominio

nuevo queda marcado.

Lo caro es descubrirlo después de enviar. El caso típico: una agencia arma una base desde sitios de

empresas y formularios viejos, la importa al CRM y manda todo junto. El proveedor acepta, devuelve rebotes y pausa la cuenta "hasta que se limpie la

lista". Ahí empieza la tarea previa: separar qué dominios reciben correo y cuáles van a rebotar.

Un script corto, sin dependencias, hace ese filtro con DNS. Después explico qué no cubre y cómo medir la

tasa de rebote real en vez de estimarla.

Los errores que aparecen siempre en una lista de 1.000

1. Sintaxis que pasa el regex pero el servidor rechaza. Un punto al final, dos arrobas, un guion bajo

en el dominio: el regex acepta y el MX no existe.

2. Dominio sin MX ni registro A. Se compró para el sitio y nunca se configuró el correo: el rebote más

común y el más fácil de detectar.

3. Catch-all tratado como válido. El servidor acepta cualquier dirección de ese dominio: un chequeo

SMTP responde "entregable" para cualquiercosa@empresa.com. Lo honesto es marcar el dominio.

4. Dominios desechables. mailinator.com y parientes, que entran desde formularios y exportaciones.

Nunca van a leer nada.

5. Cuentas de rol. info@, ventas@, no-reply@: no son inválidas, pero bajan la respuesta. Se

etiquetan, no se borran.

6. Typo del proveedor. gmai.com, hotmal.com. El dominio existe y recibe correo: el rebote no lo

delata.

7. Duplicados que el CRM no ve. Juan@empresa.com y juan@empresa.com, o juan+news@. El mismo

buzón dos veces infla la lista y duplica el riesgo de queja.

Ninguno se detecta mirando la lista: se detectan consultando DNS, gratis y sin enviar nada.

El script

Node 18 o superior, solo node:dns/promises: no hay npm install.


// email-preflight.mjs — uso: node email-preflight.mjs emails.txt salida.csv
import { readFile, writeFile } from 'node:fs/promises';
import { resolveMx, resolve4, resolveTxt } from 'node:dns/promises';

const [, , listPath, out = 'emails.csv'] = process.argv;
if (!listPath) { console.error('Uso: node email-preflight.mjs emails.txt [salida.csv]'); process.exit(1); }

// Lista corta: los descartables rotan seguido.
const DESECHABLES = new Set(['mailinator.com', 'guerrillamail.com', '10minutemail.com', 'tempmail.com',
  'yopmail.com', 'trashmail.com', 'sharklasers.com', 'getnada.com']);
const ROL = new Set(['info', 'ventas', 'sales', 'contacto', 'contact', 'admin', 'soporte', 'support',
  'hola', 'hello', 'noreply', 'no-reply', 'postmaster', 'webmaster']);
const PROVEEDORES = ['gmail.com', 'hotmail.com', 'outlook.com', 'yahoo.com', 'icloud.com', 'live.com'];
const RE = /^[^\s@]+@[^\s@.]+(\.[^\s@.]+)+$/;

function distancia(a, b) {
  let prev = [...Array(b.length + 1).keys()];
  for (let i = 1; i <= a.length; i++) {
    const cur = [i];
    for (let j = 1; j <= b.length; j++)
      cur[j] = Math.min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (a[i - 1] === b[j - 1] ? 0 : 1));
    prev = cur;
  }
  return prev[b.length];
}

async function txt(name) {
  try { return (await resolveTxt(name)).map((r) => r.join('')); } catch { return []; }
}

async function revisarDominio(dominio) {
  const [mx, a, raiz, dmarcTxt] = await Promise.all([
    resolveMx(dominio).catch(() => []),
    resolve4(dominio).catch(() => []),
    txt(dominio),
    txt(`_dmarc.${dominio}`),
  ]);
  const dmarc = dmarcTxt.find((t) => /^v=dmarc1\b/i.test(t)) ?? '';
  return {
    mx: mx.sort((x, y) => x.priority - y.priority).map((m) => m.exchange.replace(/\.$/, '')),
    tieneA: a.length > 0,
    spf: raiz.some((t) => /^v=spf1\b/i.test(t)),
    dmarc: (dmarc.match(/\bp\s*=\s*(none|quarantine|reject)/i)?.[1] ?? '').toLowerCase(),
  };
}

const lineas = (await readFile(listPath, 'utf8')).split('\n').map((l) => l.trim().toLowerCase())
  .filter((l) => l && !l.startsWith('#'));
const vistos = new Set(['']), cache = new Map(), filas = [];

for (const email of lineas) {
  if (vistos.has(email)) continue;
  vistos.add(email);
  const [buzon, dominio = ''] = email.split('@');
  const fila = { email, dominio, mx: '', veredicto: 'SINTAXIS', notas: '' };

  if (RE.test(email) && email.length <= 254) {
    if (!cache.has(dominio)) cache.set(dominio, revisarDominio(dominio));
    const d = await cache.get(dominio);
    fila.mx = d.mx.length ? d.mx[0] : d.tieneA ? '(A implícito)' : '';
    if (DESECHABLES.has(dominio)) fila.veredicto = 'DESECHABLE';
    else if (!d.mx.length && !d.tieneA) fila.veredicto = 'SIN_MX';
    else fila.veredicto = 'RECIBE';

    const notas = [];
    if (ROL.has(buzon)) notas.push('rol');
    if (buzon.includes('+')) notas.push('alias');
    if (PROVEEDORES.some((p) => p !== dominio && distancia(dominio, p) <= 2)) notas.push('typo?');
    if (!d.spf) notas.push('sin-spf');
    if (!d.dmarc) notas.push('sin-dmarc');
    else if (d.dmarc === 'none') notas.push('dmarc-none');
    fila.notas = notas.join(' ');
  }
  filas.push(fila);
  await new Promise((r) => setTimeout(r, 30));
}

const headers = ['email', 'dominio', 'mx', 'veredicto', 'notas'];
const cell = (v) => `"${String(v ?? '').replace(/"/g, '""')}"`;
const csv = [headers.join(','), ...filas.map((f) => headers.map((h) => cell(f[h])).join(','))].join('\n');
await writeFile(out, csv, 'utf8');

const cuenta = (v) => filas.filter((f) => f.veredicto === v).length;
console.log(`${filas.length} únicos · RECIBE ${cuenta('RECIBE')} · SIN_MX ${cuenta('SIN_MX')} · ` +
  `DESECHABLE ${cuenta('DESECHABLE')} · SINTAXIS ${cuenta('SINTAXIS')} → ${out}`);

printf '%s\n' juan@estudio-sur.com.ar info@logistica-norte.com ventas@gmai.com > emails.txt
node email-preflight.mjs emails.txt salida.csv

La columna veredicto ordena el trabajo: SIN_MX y DESECHABLE se borran, SINTAXIS se corrige a

mano; RECIBE con rol va a otra secuencia.

Tres detalles que importan

  • Caché por dominio. Mil contactos pueden salir de ochenta dominios: sin caché el script hace mil

consultas en vez de ochenta y el resolver público devuelve SERVFAIL.

  • Registro A como respaldo del MX. Por la RFC 5321, sin MX el correo va al registro A; marcarlos

SIN_MX te hace borrar contactos válidos.

  • SPF y DMARC del dominio. No dicen si el buzón existe, pero sí cuánto pesa tu envío.

Por qué acá no hay verificación SMTP

Para saber si un buzón existe hay que hablar SMTP: puerto 25, RCPT TO:<buzon>, leer el código.

1. El puerto 25 suele estar bloqueado. Hostings y conexiones domésticas lo cierran para frenar spam:

falla por red, no por el contacto.

2. Greylisting. El servidor responde 4xx "intentá después" a un remitente desconocido. Un

verificador mal escrito lo lee como inválido y borra contactos buenos.

3. Reputación. Sondeos masivos queman la IP que después envía.

Aun resolviendo los tres, el catch-all sigue sin respuesta. Por eso el script es DNS puro: afirma lo que

se puede afirmar sin tocar el servidor del otro.

La tasa de rebote real se lee, no se estima

El único dato real lo devuelve el envío, y conviene no mezclar duro con blando.


// rebotes.mjs — export del proveedor: email,status,reason
import { readFile } from 'node:fs/promises';

const csv = await readFile(process.argv[2] ?? 'envio.csv', 'utf8');
const filas = csv.trim().split('\n').slice(1).map((l) => l.split(','));

const duros = filas.filter((f) => /hard|permanent|5\.\d/i.test(f.slice(1).join(' ')));
const blandos = filas.filter((f) => /soft|temporary|4\.\d/i.test(f.slice(1).join(' ')));
const pct = (n) => ((n / filas.length) * 100).toFixed(2);

console.log(`enviados ${filas.length} · duros ${duros.length} (${pct(duros.length)}%) · ` +
  `blandos ${blandos.length} (${pct(blandos.length)}%)`);

Duro es "esta dirección no existe": se borra. Blando es buzón lleno, servidor caído o greylisting: se

reintenta. Sumarlos hace que la lista parezca peor de lo que es —o mejor, si el proveedor solo muestra el

total. Y un duro posterior a un DNS RECIBE es esperable: el dominio recibe correo, ese buzón no.

Lo que este script no cubre

  • Que el buzón exista. Sin SMTP no se sabe; con SMTP el catch-all miente igual.
  • Que la persona siga en la empresa. Se resuelve con fecha de origen, no con DNS.
  • Trampas de spam. MX válido, veredicto RECIBE, cero interés: ninguna verificación técnica las ve.
  • Base legal. Un email corporativo es dato personal: bajo Ley 25.326, LGPD o GDPR importan base de

licitud, información al titular y baja. Esto no reemplaza una revisión legal.

  • Reputación del emisor. Tu SPF, DKIM y DMARC se miran en el proveedor de envío.
  • Listas nuevas de descartables. La del script es corta y envejece.

contactos. Si casi todo da RECIBE y aun así rebota, el problema está después del DNS.
