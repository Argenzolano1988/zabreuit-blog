Por qué Google no muestra el precio de tus productos: auditar el JSON-LD en lote

El precio desaparece de Google cuando el JSON-LD del producto está roto o no existe. Se detecta en lote con 90 líneas de Node, sin herramientas de pago.

Un catálogo de 800 SKU, un tema nuevo, un plugin de reseñas. A la semana siguiente, el precio ya no aparece en los resultados de búsqueda y en Search Console no hay un error que diga "este producto perdió el precio". Hay una lista de URLs con problemas, un informe que llega con días de atraso y la sensación de estar buscando a ciegas.

El problema se puede reducir a una pregunta concreta: ¿qué devuelve el HTML de cada página de producto cuando lo pedís con curl? Todo lo demás —Rich Results Test, Search Console, la extensión de SEO— es una forma más lenta de responder lo mismo.

Por qué el test manual no alcanza

El Rich Results Test valida una URL por vez y no tiene API pública. Con 800 productos, revisar el catálogo a mano es media jornada de trabajo, y esa media jornada vence en cuanto alguien toca el tema.

Search Console sí es masivo, pero llega tarde y solo para páginas indexadas. El informe de Datos estructurados no analizables agrupa por tipo de error, no por plantilla: te dice que hay 400 páginas con JSON inválido, no que las 400 salen del mismo componente del tema. Sin esa distinción, el arreglo es adivinanza.

Un script propio responde en minutos y con el HTML real que ve un cliente que abre la página con JavaScript desactivado, que es lo que Google recomienda para marcado de producto: "If you're a merchant optimizing for all types of shopping results, we recommend putting Product structured data in the initial HTML for best results".

Las seis causas que aparecen en una corrida real

Los seis aparecen en catálogos grandes. En la corrida de seis URLs que muestro más abajo salieron tres de ellos, y los otros tres son los que encontrás en cuanto el lote pasa de cien páginas: no son teóricos, son los que el test manual nunca llega a ver.

1. Precio con formato local. "price": "1.234,56" es como se escribe un precio en Argentina y es exactamente lo que Google no puede leer. price es un número: separador decimal punto, sin separador de miles, sin símbolo de moneda. El error no salta a la vista porque el string es válido; el problema es semántico.

2. priceCurrency faltante. Para product snippets Google lo recomienda; para merchant listings (las fichas de compra) lo exige. Sin moneda, un precio de 19.99 puede ser dólares, euros o reales, y Google no adivina. Tres letras ISO 4217: ARS, MXN, CLP, USD.

3. offers sin price. Pasa con productos de precio variable: el tema emite un Offer vacío porque el precio se calcula en el cliente. La forma correcta para un rango es AggregateOffer con lowPrice y priceCurrency; price solo existe en Offer.

4. JSON que no parsea. Una coma final, una comilla sin escapar, un "price": 19,99 escrito a mano en el template. Search Console lo reporta como no analizable, pero el bloque se ve perfectamente en el código fuente hasta que lo pasás por JSON.parse.

5. ProductGroup sin Product. Los temas nuevos de Shopify agrupan variantes en un ProductGroup con hasVariant. Google documenta ese formato, pero pide además el marcado de Product con los datos de la variante (product variants). Si tu validador busca solo Product en el nivel superior y no entra en hasVariant, reporta la página como vacía. Falso negativo, y de los caros: te hace reescribir un marcado que ya estaba bien.

6. Dos precios distintos en la misma página. Tema y plugin emiten cada uno su Product, uno con el precio de lista y otro con el precio de oferta. Google toma uno y no avisa cuál. En la auditoría aparece como dos nodos con precios que no coinciden.

Un detalle al revés: availability acepta la URL completa (https://schema.org/InStock) y el nombre corto (InStock). Un validador casero que solo acepte la URL marca un error que no existe. Menos falsos positivos es más importante que más reglas.

El script

Node 18 o superior, cero dependencias, sin headless browser. Pide el HTML crudo, extrae cada bloque application/ld+json, lo aplana (@graph y hasVariant) y aplica las reglas de arriba.


#!/usr/bin/env node
// jsonld-audit.mjs — audita el marcado Product (JSON-LD) de una lista de URLs.
// Uso: node jsonld-audit.mjs urls.txt > reporte.csv
import { readFileSync } from 'node:fs';

const UA = 'Mozilla/5.0 (compatible; jsonld-audit/1.0)';
const BLOCK = /<script[^>]+type=["']application\/ld\+json["'][^>]*>([\s\S]*?)<\/script>/gi;
const PRICE = /^\d+(\.\d{1,2})?$/;
const SO = /^https?:\/\/schema\.org\/[A-Za-z]+$/;

const urls = readFileSync(process.argv[2], 'utf8')
  .split('\n').map((l) => l.trim()).filter((l) => l && !l.startsWith('#'));

function flatten(node, out = []) {
  if (Array.isArray(node)) return node.reduce((acc, n) => flatten(n, acc), out);
  if (!node || typeof node !== 'object') return out;
  if (Array.isArray(node['@graph'])) flatten(node['@graph'], out);
  if (Array.isArray(node.hasVariant)) flatten(node.hasVariant, out);
  out.push(node);
  return out;
}

const typesOf = (n) =>
  [].concat(n['@type'] ?? []).map((t) => String(t).replace(/^https?:\/\/schema\.org\//i, ''));

function issuesOf(p) {
  const bad = [];
  if (!p.name) bad.push('sin name');
  const offers = [].concat(p.offers ?? []);
  if (!offers.length) bad.push('sin offers');
  for (const o of offers) {
    const raw = o.price ?? o.lowPrice ?? o.priceSpecification?.price;
    const cur = o.priceCurrency ?? o.priceSpecification?.priceCurrency;
    const avail = o.availability;
    if (raw == null) bad.push('offer sin price');
    else if (!PRICE.test(String(raw).replace(/^"(.*)"$/, '$1'))) bad.push(`price inválido: ${raw}`);
    if (!/^[A-Z]{3}$/.test(String(cur ?? ''))) bad.push(`priceCurrency: ${cur ?? 'falta'}`);
    if (avail && !SO.test(String(avail)) && !/^[A-Z][A-Za-z]+$/.test(String(avail)))
      bad.push(`availability inválida: ${avail}`);
  }
  return bad;
}

async function audit(url) {
  const ctrl = new AbortController();
  const t = setTimeout(() => ctrl.abort(), 15000);
  try {
    const res = await fetch(url, { headers: { 'user-agent': UA }, signal: ctrl.signal, redirect: 'follow' });
    const html = await res.text();
    const blocks = [...html.matchAll(BLOCK)].map((m) => m[1]);
    const nodes = [];
    const parseErrors = [];
    for (const raw of blocks) {
      try {
        flatten(JSON.parse(raw.replace(/^\uFEFF/, '').trim()), nodes);
      } catch {
        parseErrors.push(raw.trim().slice(0, 60).replace(/\s+/g, ' '));
      }
    }
    const products = nodes.filter((n) => typesOf(n).includes('Product'));
    const groups = nodes.filter((n) => typesOf(n).includes('ProductGroup'));
    const prices = products
      .flatMap((p) => [].concat(p.offers ?? []))
      .map((o) => o.price ?? o.lowPrice ?? o.priceSpecification?.price)
      .filter((v) => v != null)
      .map(String);
    const bad = [
      ...products.flatMap(issuesOf),
      ...groups.filter((g) => !g.name).map(() => 'ProductGroup sin name'),
      ...(new Set(prices).size > 1 ? [`precios en conflicto: ${[...new Set(prices)].join(' / ')}`] : []),
    ];
    const microdata = /itemtype=["'][^"']*schema\.org\/Product/i.test(html);
    return {
      url, status: res.status, products: products.length, groups: groups.length,
      blocks: blocks.length, parseErrors, microdata, issues: [...new Set(bad)],
    };
  } catch (e) {
    return { url, status: 0, products: 0, groups: 0, blocks: 0, parseErrors: [], microdata: false, issues: [`fetch: ${e.name}`] };
  } finally {
    clearTimeout(t);
  }
}

const rows = [];
for (let i = 0; i < urls.length; i += 4) {
  rows.push(...(await Promise.all(urls.slice(i, i + 4).map(audit))));
}

const q = (s) => `"${String(s).replace(/"/g, '""')}"`;
console.log('url,status,productos,grupos,bloques,errores_json,problemas');
for (const r of rows) {
  const flags = [
    ...r.issues,
    ...(r.parseErrors.length ? [`json roto: ${r.parseErrors[0]}`] : []),
    ...(r.products + r.groups === 0 && r.microdata ? ['solo microdata'] : []),
    ...(r.products + r.groups === 0 && !r.microdata ? ['sin marcado Product'] : []),
  ];
  console.log([q(r.url), r.status, r.products, r.groups, r.blocks, r.parseErrors.length, q(flags.join('; '))].join(','));
}

Cuatro decisiones que importan cuando el catálogo es grande:

  • HTML crudo, no DOM. No necesitás Playwright: el marcado que Google lee está en el HTML inicial. Si no está ahí, el problema es real y no un artefacto de la herramienta.
  • Concurrencia 4. Suficiente para 800 URLs en pocos minutos, bajo el umbral donde la mayoría de los WAF empiezan a cortar.
  • El status va en el CSV. Un 429 no significa "sin marcado". Significa que el servidor no te dejó leer y que ese resultado no sirve como evidencia.
  • Un archivo, una foto. Guardá reporte-2026-11-20.csv. La auditoría vale por el diff contra el de la semana anterior: cuando alguien actualiza el tema, las páginas que cambian de estado aparecen solas.

Cómo leer la salida

La corrida real sobre seis URLs devolvió tres cosas distintas, y las tres importan:

  • Tres páginas con 200 y cero bloques JSON-LD. No hay marcado. Ningún plugin lo emite, o lo emite por JavaScript después del render. Es el caso más grave y el más fácil de arreglar.
  • Una página con Product y offers sin price ni priceCurrency. Precio variable mal modelado: le falta AggregateOffer.
  • Dos 429. La misma URL, pedida de nuevo sin concurrencia, devolvió 200 y un ProductGroup con las variantes completas. Si el script no imprimiera el status, habría reportado dos páginas sanas como rotas y el arreglo habría ido al lugar equivocado.

Ese último punto es la razón por la que conviene correr el script contra producción de noche, con concurrencia 1 o 2, y volver a pasar las URLs que devolvieron error antes de abrir un ticket.

De seis URLs a cinco mil

El insumo es el sitemap.xml que ya tenés. Bajalo, filtrá las URLs de producto (el patrón /producto/, /p/, /products/ suele alcanzar), deduplicá y cortá en lotes de 500. El CSV de cada lote se concatena y el diff semanal te da tres listas: páginas que perdieron el marcado, páginas que ganaron errores nuevos, páginas que se arreglaron.

Un cron semanal alcanza. Diario es ruido: Google no reindexa a esa velocidad y los cambios de tema se despliegan por sprint, no por día.

Cuando una sola página no cuadra

El lote te dice cuáles páginas están mal. Para entender por qué una página específica emite lo que emite, el CSV no sirve: necesitás ver el bloque completo, el estado SSR y los tipos inferidos. Para eso está la extensión Zabreuit Web State & Schema Inspector para VS Code y Cursor: abre una URL, lista los bloques JSON-LD y el estado embebido, y genera las interfaces TypeScript o el esquema Zod del objeto, que es lo que necesitás para tipar el fix sin adivinar la forma del dato.
