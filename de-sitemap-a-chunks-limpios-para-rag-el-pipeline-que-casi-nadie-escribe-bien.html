De sitemap a chunks limpios para RAG: el pipeline que casi nadie escribe bien

La mitad de los RAG que fallan no fallan por el modelo: fallan porque los documentos entraron con menús, cookies y "acepto todo". Este pipeline saca Markdown limpio desde el sitemap, con Node.js y cero dependencias.

Un caso concreto: tenés 400 URLs de documentación en un sitemap.xml y querés que tu agente responda con eso. Lo primero que aparece en el tutorial es Cheerio + LangChain + un splitter de 1.000 caracteres. El índice queda armado en veinte minutos y las respuestas salen mal por una razón que no está en el código del agente: los chunks contienen el header de navegación, el banner de cookies, los links al pie y el aviso legal. El modelo recupera "Inicio · Productos · Contacto · Política de cookies" y lo usa como contexto.

El orden correcto es al revés del que sugiere el tutorial: primero extraer texto de verdad, después cortar. Un chunk mal extraído no se arregla cambiando de modelo ni de base vectorial.

Paso 0: leer el sitemap como lo que es

Un sitemap.xml es un índice, no una lista de artículos. Puede tener sitemapindex anidado, lastmod y URLs de etiquetas, autores y paginación que no aportan conocimiento.


// sitemap.mjs — devuelve URLs de contenido, no de navegación
const SKIP = /\/(tag|tags|category|author|page|search|cart|login|account)\b/i;

async function fetchText(url) {
  const res = await fetch(url, { headers: { "user-agent": "zabreuit-docs-crawler/1.0" } });
  if (!res.ok) throw new Error(`${res.status} ${url}`);
  return res.text();
}

export async function sitemapUrls(start, seen = new Set()) {
  const xml = await fetchText(start);
  const locs = [...xml.matchAll(/<loc>\s*([^<\s]+)\s*<\/loc>/gi)].map((m) => m[1]);
  const urls = [];
  for (const loc of locs) {
    if (seen.has(loc)) continue;
    seen.add(loc);
    if (/\.xml(\.gz)?$/i.test(loc)) {
      urls.push(...(await sitemapUrls(loc, seen))); // sitemapindex
    } else if (!SKIP.test(new URL(loc).pathname)) {
      urls.push(loc);
    }
  }
  return urls;
}

Antes de crawlear, dos chequeos de cortesía que también son técnicos: robots.txt (qué rutas pide no visitar) y llms.txt (si el sitio ya publica su contexto para modelos, usalo y ahorrate el crawl).

Paso 1: aislar el contenido real

Toda página de documentación tiene tres zonas: navegación, contenido y pie. El contenido vive en <main>, <article> o en el <div> con más párrafos. Esa última heurística salva los sitios viejos sin HTML semántico.


// extract.mjs — texto del bloque con más prosa
const DROP = /<(script|style|nav|header|footer|aside|form|noscript|svg|iframe)[\s\S]*?<\/\1>/gi;

const textLen = (html) =>
  html.replace(/<[^>]+>/g, " ").replace(/\s+/g, " ").trim().length;

export function mainContent(html) {
  const clean = html.replace(/<!--[\s\S]*?-->/g, "").replace(DROP, " ");

  const semantic = clean.match(/<(main|article)\b[^>]*>([\s\S]*?)<\/\1>/i);
  if (semantic && textLen(semantic[2]) > 400) return semantic[2];

  // sin etiqueta semántica: el div con más texto suele ser el artículo
  const blocks = [...clean.matchAll(/<div\b[^>]*>([\s\S]*?)<\/div>/gi)];
  let best = "", bestLen = 0;
  for (const [, inner] of blocks) {
    const paragraphs = (inner.match(/<p\b/gi) ?? []).length;
    const len = textLen(inner);
    if (paragraphs >= 3 && len > bestLen) { best = inner; bestLen = len; }
  }
  return best || clean;
}

Si el texto extraído tiene menos de ~300 caracteres, la página es un shell de JavaScript o un 404 blando: se descarta. Un RAG con páginas vacías es peor que un RAG más chico.

Paso 2: HTML a Markdown, con la estructura que importa

Para recuperar contexto, el Markdown tiene que conservar títulos, listas y bloques de código. El resto (clases, divs, atributos) es ruido.


// to-markdown.mjs — subconjunto honesto: títulos, párrafos, listas, código, tablas
export function toMarkdown(html) {
  return html
    .replace(/<pre[^>]*>([\s\S]*?)<\/pre>/gi, (_, code) =>
      "\n```\n" + decode(code.replace(/<[^>]+>/g, "")) + "\n```\n")
    .replace(/<h([1-6])[^>]*>([\s\S]*?)<\/h\1>/gi, (_, n, t) =>
      "\n" + "#".repeat(Number(n)) + " " + inline(t) + "\n")
    .replace(/<li[^>]*>([\s\S]*?)<\/li>/gi, (_, t) => "\n- " + inline(t))
    .replace(/<blockquote[^>]*>([\s\S]*?)<\/blockquote>/gi, (_, t) =>
      "\n> " + inline(t) + "\n")
    .replace(/<p[^>]*>([\s\S]*?)<\/p>/gi, (_, t) => "\n\n" + inline(t) + "\n")
    .replace(/<br\s*\/?>/gi, "\n")
    .replace(/<[^>]+>/g, " ")
    .replace(/[ \t]+/g, " ")
    .replace(/\n{3,}/g, "\n\n")
    .trim();
}

const decode = (s) =>
  s.replace(/&lt;/g, "<").replace(/&gt;/g, ">").replace(/&amp;/g, "&")
   .replace(/&quot;/g, '"').replace(/&#39;/g, "'");

const inline = (s) =>
  decode(s.replace(/<[^>]+>/g, " "))
    .replace(/[ \t]+/g, " ")
    .replace(/\[([^\]]+)\]\([^)]*\)/g, "$1") // los links relativos no sirven fuera del sitio
    .trim();

Paso 3: cortar por secciones, no por caracteres

El splitter por longitud parte una tabla al medio y deja el encabezado en el chunk anterior. Cortar por títulos (##) mantiene cada sección completa y autocontenida; el título entra como prefijo del texto que se embebe, que es lo que hace recuperable al chunk.


// chunk.mjs
export function chunkByHeading(md, { maxChars = 1800, minChars = 200 } = {}) {
  const parts = md.split(/\n(?=#{2,3} )/);
  const chunks = [];
  for (const part of parts) {
    const heading = part.match(/^#{2,3} (.+)$/m)?.[1] ?? "";
    if (part.trim().length <= maxChars) {
      if (part.trim().length >= minChars) chunks.push({ heading, text: part.trim() });
      continue;
    }
    // sección larga: cortar en párrafos, arrastrando el título
    let buf = "";
    for (const para of part.split(/\n{2,}/)) {
      if ((buf + para).length > maxChars && buf) {
        chunks.push({ heading, text: buf.trim() });
        buf = "";
      }
      buf += para + "\n\n";
    }
    if (buf.trim().length >= minChars) chunks.push({ heading, text: buf.trim() });
  }
  return chunks;
}

Dos detalles que cambian la calidad del índice: el heading va como campo aparte y se antepone al texto embebido (${heading}\n\n${text}); y los chunks de menos de 200 caracteres se descartan salvo que sean notas cortas con valor propio.

Paso 4: emitir JSONL y deduplicar

Un solo archivo, una línea por chunk, con url, heading, text y un hash de contenido. El hash detecta el mismo texto en v1/ y v2/ de la documentación y evita pagar dos veces por el mismo embedding.


// run.mjs — pipeline completo
import { createHash } from "node:crypto";
import { writeFileSync } from "node:fs";

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const seen = new Set();
const out = [];

const urls = await sitemapUrls("https://docs.ejemplo.com/sitemap.xml");
for (const url of urls) {
  const html = await fetchText(url);
  const chunks = chunkByHeading(toMarkdown(mainContent(html)));
  for (const c of chunks) {
    const key = createHash("sha1").update(c.text).digest("hex");
    if (seen.has(key)) continue;
    seen.add(key);
    out.push(JSON.stringify({ url, ...c, hash: key }));
  }
  await sleep(400); // cortesía: 2-3 req/s como máximo
}

writeFileSync("docs.jsonl", out.join("\n") + "\n");
console.log(`${urls.length} URLs → ${out.length} chunks únicos`);

Con eso tenés docs.jsonl y podés embeber con el proveedor que quieras. El crawl de 400 páginas tarda unos minutos y no cuesta nada más que tu tiempo.

Donde este pipeline se rompe

Vale decirlo antes de que lo descubras en producción:

  • Documentación renderizada en el cliente. Si el contenido no está en el HTML inicial, fetch devuelve el shell. Ahí necesitás un navegador headless y el costo se multiplica por diez.
  • Sitios con sitemap incompleto o inexistente. Toca descubrir URLs por enlaces internos desde la home, con profundidad limitada, y aceptar que vas a dejar cosas afuera.
  • Contenido detrás de login o de un plan pago. No hay pipeline que lo resuelva; eso es un acuerdo comercial, no un problema técnico.
  • Documentación que cambia todos los días. El crawl puntual sirve una vez; mantenerlo es un cron, un diff por hash y un re-embedding incremental.
  • Textos de interfaz dentro de <main>. Un "Última actualización: … · Copiar como Markdown" no es navegación y la heurística no lo saca. Se limpia con una denylist de frases cortas y revisando a mano los primeros diez chunks; no hay magia que lo resuelva solo.
  • Sitios que prohíben el crawl en robots.txt o en sus términos. Se respeta. Hay alternativas legales (API oficial, feed, licencia de datos) y ninguna es "ignorar el archivo".
